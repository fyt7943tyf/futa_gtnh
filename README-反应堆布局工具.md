# IC2 反应堆布局工具（FutaGTNH）

给 IC2 核反应堆加一套「**摆法存档 + 一键复刻**」：
把调好的反应堆内部摆放（燃料棒/散热组件/反射板…）记录成全服共享的档案，
之后在任何一台同类反应堆上**一键部署**，材料自动从玩家背包和共享背包里抽；
流体反应堆的 5×5×5 压力容器外壳也能一键填满。

---

## 怎么拿到

合成「核反应堆布局工具」（永久工具，不消耗）：

```
钢板   纸   钢板
纸    钻石  纸
钢板   纸   钢板
```

`plateSteel` / `gemDiamond` 走矿物词典；纸用原版纸张。

## 怎么用

| 操作 | 效果 |
| --- | --- |
| **Shift + 右键反应堆**（核心或反应堆仓） | 记录它的内部摆放到全服档案，聊天栏给出条目名 |
| **右键反应堆** | 打开档案浏览器，右键点中的那台就是**部署目标**：选中布局 → 「部署到目标」；流体反应堆没包壳时点「建造外壳」；顺手可「保存当前布局」 |
| **右键空气** | 纯管理模式：浏览 / 预览 / 重命名 / 删除（没有部署按钮） |

目标识别很宽容：点到**核心、反应堆仓、外壳方块**（检修孔/流体端口/红石端口）都能找到那台反应堆。

## 浏览器界面

- **左栏**：档案列表（蓝点=流体反应堆，绿点=普通；右侧是列数 3~9）。
- **右栏**：选中布局的 6×N 网格预览（N = 3 + 反应堆仓数，和 IC2 网格一一对应），
  悬停看原件完整 tooltip；下面是**需求清单**——每种元件「需要 ×N｜背包 a｜共享 b」：
  绿色 = 有 NBT 完全一致的存货；黄色 = 够但靠不同损耗顶替；红色 = 不够。
- **NBT 宽松匹配开关**：见下节。

## 部署语义（重要）

1. **先清空后铺设**：目标网格里已有的东西**全部回收到共享背包**，然后按布局逐格铺。
   目标比布局宽（反应堆仓更多）时，多出来的列也会被清空。
2. **取料顺序**：玩家背包优先，共享背包补足（与匠魂自动补料同一套习惯）。
3. **缺料不虚发**：缺多少报告多少，凑不齐的格子空着。
4. 布局记录的是普通反应堆、目标是流体反应堆（或反过来）时**只警告不拦**——
   两者的内部网格是通用的，决定权在玩家。
5. 目标网格比布局**窄**（反应堆仓更少）时拒绝：放不下。

## NBT 难点：为什么需要「宽松匹配」

IC2 的燃料棒/散热组件把损耗记在**物品栈 NBT**里（`ItemGradualInt` 的 `advDmg` 整型；
全新件没有 NBT）。从运行中的反应堆记录下来的布局，燃料棒几乎必然带着「已损耗」的 NBT；
而共享背包里备的料是全新件。共享背包的条目身份是「物品 + 耐久 + NBT 全一致」
（见 `shared/ItemKey`），按档案**精确**等值请求永远请求不到。

所以部署取料走**三级匹配**：

1. **精确**：档案里的完整 NBT 在背包/共享背包里找——全新件档案走这条，逐字节一致；
2. **宽松**（默认开，GUI 可关）：同「物品 + 耐久」、任意 NBT 的存货合并计数，
   优先取**最接近全新**的变体（无 NBT → `advDmg` 小）。用过的档案配全新库存在这条落地；
3. **缺料**：两级都凑不齐的差额进报告。

宽松匹配拿到的元件**保持它自己的 NBT**——不把新件改成旧件的损耗（不造假），
新件装进去只会更好。清单上的黄色标注就是「这些格子装的不是逐字节同款」。

## 流体反应堆外壳

「建造外壳」把核心周围 5×5×5 的壳层（3×3×3 之外的那 98 格）用**反应堆压力容器**
填满（`IC2Items.getItem("reactorvessel")`）。规则：

- 需要满配反应堆（6 个反应堆仓），否则拒绝；
- 只往空气/可替换方块放；已有容器的格子跳过；有生物站着的格子跳过（不把人封进去）；
- 材料同样「玩家背包优先、共享背包补足」，缺料摆多少算多少；
- **只摆容器本体**——检修孔、流体端口、红石端口请自己挖换
  （没有检修孔打不开反应堆 GUI，没有流体端口抽不出热冷却液）。

## 数据与配置

- 档案是**全服共享**的：`<存档>/data/futa_gtnh_reactor_layouts.dat`，
  与共享背包同一套落盘保障（`.tmp` 原子写 + `.bak` 回退），重启服务器不丢。
- `config/futa_gtnh.cfg`：
  - `enableReactorTool`：总开关（默认开）；
  - `reactorToolMaxLayouts`：档案容量上限（默认 100，满了拒绝新增）。

## 技术要点（写给维护者）

- **IC2 访问全部收在 `reactor/Ic2ReactorCompat`**：只用 `ic2.api.reactor.IReactor`
  （`getItemAt/setItemAt/isFluidCooled/getPosition`）和 `IReactorChamber.getReactor()`。
  网格坐标语义（javap 证实）：x=列 `[0, 3+仓数)`，y=行 `[0,6)`，越界静默。
  列数优先反射调核心 Tile 的 `getReactorSize()`，失败退回手数相邻反应堆仓。
- 布局序列化刻意不用 `ItemStack.writeToNBT`（short 截断坑，同 `ItemKey`），
  全部写 int。
- 网络包 4 个：`PacketReactorToolUse`(37, C2S)、`PacketReactorLayoutAction`(38, C2S)、
  `PacketReactorLayoutSync`(39, S2C 分片列表)、`PacketReactorLayoutPreview`(40, S2C 单条预览)。
  Shift 记录必须走自有包——1.7.10 的 `onItemUseFirst` 返回 true 会吞掉原生 C08
  （见 `ItemReactorLayoutTool` 类注释）。
- 界面是纯客户端 `GuiScreen`（无 Container），镜像在 `client/ClientReactorLayoutCache`；
  列表只同步元数据，54 格内容按需走预览包。
- 部署/外壳动共享背包后必须 `SharedStorageManager.broadcastItemChange`，
  否则开着终端的玩家看到的是旧数字。

## 手动测试清单（开发验证用，未在游戏内跑过）

1. **合成与注册**：按上方配方合成工具；创造栏工具页可见；贴图正常。
2. **记录**：搭一台普通反应堆（核心 + 6 仓，放几根棒/散热片），Shift+右键核心
   → 聊天栏「已记录布局」；再 Shift+右键**反应堆仓**、**外壳方块**同样能记。
3. **浏览**：右键空气打开浏览器；列表有刚才那条；选中后右侧网格与之一一对应。
4. **改名/删除**：输入新名点重命名 → 列表更新；删除需点两次（确认）。
5. **部署**：把反应堆清空，右键核心 → 选布局 → 部署：
   - 网格恢复成记录时的样子；
   - 聊天栏报告「铺设 N 格，回收 M 件」；
   - 开着共享背包终端时数量实时变化（broadcastItemChange 生效）。
6. **NBT 顶替**：先跑一会儿反应堆让燃料棒带上 `advDmg` 再记录；清空后往共享背包
   放**全新**燃料棒；部署 → 清单/聊天栏出现「顶替」提示，棒被装入且是全新状态。
7. **缺料**：共享背包拿空再部署 → 红色缺料清单，反应堆只铺到有料的部分。
8. **清空回收**：部署前先往反应堆里塞几组杂物 → 部署后杂物出现在共享背包。
9. **外壳**：流体反应堆（满配 6 仓）点「建造外壳」→ 98 格壳层补满压力容器；
   不足 6 仓时拒绝并提示；材料不足时按现有数量摆放并报缺料；
   重复点第二次 → 「外壳已完整」。
10. **持久化**：保存几条布局后重启服务器/单人存档 → 档案还在
    （`data/futa_gtnh_reactor_layouts.dat` + `.bak`）。
11. **专用服务器**：客户端/服务端分离部署下以上流程全部可用（语言键两端各自翻译）。
