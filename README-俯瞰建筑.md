# 俯瞰建筑模式（RTS Build）

> 从 1.20+/NeoForge 的 RTS Building（Build From Above）移植到 1.7.10 GTNH 的核心建筑功能。
> 按一下 **G** 进入俯瞰视角，像 RTS 游戏一样从头顶操作世界：远程互动、远程搭建、形状批量建造/区域破坏、撤销重做。

---

## 快速上手

1. 按 **G**（可在按键设置里改，分类 FutaGTNH）进入俯瞰模式：
   相机会升到你头顶 20 格、以 70° 俯角对准你；
2. 鼠标移到哪，选中框就指到哪（方块/实体都可选中），颜色跟随当前模式
   （互动=黄、建造=蓝、破坏=红，超出操作半径=亮红）；
3. 想干活用光标点，想动相机用键盘/拖拽（见下）；
4. 再按 **G** 或 **ESC** 退出。

玩家本人在俯瞰模式下**原地不动**（物理照常，注意别站在悬崖边进入）。视野被限制在你周围
`rtsMaxActionRadius`（默认 128 格，画面边缘有一圈蓝色线框边界）内，服务端也会拒绝边界外的操作
（超范围的目标高亮框会变红、状态栏有红字预警）。

## 操作一览

### 顶栏与模式

画面顶部是操作栏（移植自 RTS Building 的顶栏布局）：**互动 / 建造 / 破坏** 三个模式按钮 +
**形状 / 填充** 切换按钮 + 右侧 **撤销 / 重做**。当前模式按钮亮绿高亮，切换时屏幕中上方有
2 秒的大字提示，悬停按钮有说明。**模式决定右键的行为和回车提交的含义**：

| 模式 | 右键 | 回车提交 | 切换方式 |
| --- | --- | --- | --- |
| 互动 | 互动 / 使用物品 / 开 GUI | —（提示先切模式） | V 键 / 点击顶栏按钮 |
| 建造 | 放置手中方块 | 形状建造 | 同上 |
| 破坏 | 破坏方块 | 区域破坏 | 同上 |

左键在所有模式下都是破坏/攻击；形状选点（Ctrl+左键）在所有模式下都可用。

### 相机

| 输入 | 效果 |
| --- | --- |
| W A S D | 平移（沿相机朝向） |
| Q / E | 左转 / 右转 |
| 空格 / 左Shift | 升 / 降 |
| 滚轮 | 沿视线推拉（拉近/拉远） |
| 中键拖拽 | 旋转视角（yaw/pitch） |
| 右键拖拽 | 平移视角（像拖地图，越高拖得越快） |

### 选择方块

| 输入 | 效果 |
| --- | --- |
| 数字键 1-9（含小键盘） | 切换快捷栏槽位（同步到服务端） |
| 中键单击 | 拾取准星处方块：在快捷栏里找同款并切过去（先按 item+meta 精确匹配，再按 item 兜底），找不到会提示 |

### 单块操作

| 输入 | 效果 |
| --- | --- |
| 左键 | 破坏方块 / 攻击实体 |
| 左键拖动 | 连续破坏（划线式，光标扫过每个新方块破坏一个） |
| 右键 | 按模式分流（见上表）；建造模式下 = 对方块使用手中物品（**放置就是它**） |
| Shift+右键 | 潜行语义（跳过方块互动直接用物品，例如潜行右键箱子放火把） |
| Ctrl+右键拖动 | 建造模式=连续放置（手里拿方块划线铺）；破坏模式=连续破坏 |

**生存规则（建筑完整 + 破坏简化）：**

- 放置走原版逻辑：从手上扣材料（创造不扣），与真实右键完全一致，GT 机器/特殊方块都兼容；
- 破坏即时完成（不挖进度条），但保留原版的掉落物、工具耐久、时运/精准；工具等级不够会**直接拒绝**（`rtsRequireCorrectToolForBreak`，默认开），不会出现「挖掉了但什么都不掉」的惨剧。

### 远程互动

**互动模式**下右键打开的箱子/GT 机器界面**在远处保持可用**（本模组放宽了原版「离容器太远自动关闭」的检查）。
关掉界面会自动回到俯瞰 HUD。远程打开的界面在你退出俯瞰模式后恢复原版行为（走远会关）。
所有被服务端拒绝的操作（会话失效/超范围/操作过快）现在都会给出聊天提示。

### 批量操作（形状建造 / 区域破坏）

1. 切到**建造**或**破坏**模式（V 或顶栏按钮），**B**（或 Tab）切换形状，**F** 切换填充
   （顶栏上也有这两个按钮，直接显示当前值）；
2. **Ctrl+左键** 选两个角点 A → B（按下即选，再点会重新从 A 开始），画面里实时显示幽灵预览
   （建造=蓝色，破坏=红色，互动模式=灰色且回车无效）；
3. **回车** 提交，**C** 清空选点。

| 形状 | 说明 |
| --- | --- |
| 直线 | A 到 B 的三维直线 |
| 墙面 | A、B 水平连线撑开的竖墙 |
| 平面 | A、B 水平撑开的矩形地板/天花板（Y 取 A） |
| 圆盘 / 圆柱 | 圆心取水平中点，半径取水平跨度 |
| 球 | 圆心取中点，半径取距离一半 |
| 长方体 | A、B 为对角 |

| 填充 | 说明 |
| --- | --- |
| 实心 | 整个体积 |
| 空心 | 只有外壳（盖房子） |
| 线框 | 只有棱/环（搭骨架） |

**限制**（可配置）：每条边最多 32 格、整个形状最多 32768 格；
任务在服务端按 `rtsBuildBatchBlocksPerTick`（默认每 tick 64 格）推进，不会卡服。

**批量建造的材料**：先吃背包，背包不够自动从**共享背包**补（`rtsUseSharedStorage`，默认开；
批量时手里必须拿着对应的方块物品）。两处都没料任务会中止，已放好的保留。

**批量破坏**：逐格走和单块破坏相同的规则（工具/不可破坏的方块自动跳过并在结束时汇报），
正常掉落、正常耗耐久。

### 撤销 / 重做 / 旋转

| 输入 | 效果 |
| --- | --- |
| Ctrl+Z / Ctrl+Y | 撤销 / 重做最近一次俯瞰操作（单块破坏、整个批量任务、旋转各算一条） |
| R | 旋转光标悬停的方块（原版支持旋转的都行：原木轴向、活塞朝向等；GT 机器多数不响应） |

撤销只回滚方块（含箱子等内容物的完整快照），**不回退材料**；
每栈最多 3 条、10 分钟后过期（均可配置）。

## 防护（服务器管理员）

所有操作都是服务端权威校验的：

- 必须处于俯瞰会话（服务端登记）才能发动作包；
- 每个目标都在玩家周围 `rtsMaxActionRadius` 立方体内；
- 单块操作每 tick 每玩家最多 `rtsOpsPerTickPerPlayer` 次（防灌包）；批量有独立预算；
- 批量形状由服务端按参数重新生成（客户端传不上来假坐标）；
- 破坏走原版 `tryHarvestBlock`：Forge 破坏事件、领地保护 mod 的拦截照常生效。

**已知取舍**：远程互动绕过了 `PlayerInteractEvent`（1.7.10 里该事件在 NetHandler 层触发），
依赖该事件做保护的 mod 拦不住远程右键方块；破坏类保护不受影响。
服务端远程互动本质是「把玩家临时传送 4 格（`rtsInteractReach`）执行原版逻辑再传回」，
期间不发同步包，但理论上存在向其他玩家泄漏 1 tick 位置的可能（原版 RTSbuilding 同样接受）。

## 配置（config/futa_gtnh.cfg）

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `rtsEnable` | true | 俯瞰模式总开关（服务端权威，拒绝时客户端自动退出并提示） |
| `rtsMaxActionRadius` | 128 | 操作半径（格）。客户端视距需大于半径÷16 |
| `rtsHeightMinOffset` / `rtsHeightMaxOffset` | -35 / 110 | 相机相对玩家的高度范围 |
| `rtsPickRange` | 128 | 光标拾取距离 |
| `rtsInteractReach` | 4.0 | 远程互动虚拟眼距 |
| `rtsOpsPerTickPerPlayer` | 8 | 每 tick 单块操作上限 |
| `rtsRequireCorrectToolForBreak` | true | 生存破坏要求工具等级 |
| `rtsMaxShapeDimension` / `rtsMaxSelectionVolume` | 32 / 32768 | 批量形状限制 |
| `rtsBuildBatchBlocksPerTick` | 64 | 批量任务每 tick 预算 |
| `rtsUseSharedStorage` | true | 批量材料允许从共享背包补 |
| `rtsHistoryMaxEntries` / `rtsHistoryRetentionSeconds` | 3 / 600 | 撤销栈 |
| `rtsCamera*` / `rtsMouse*` | - | 相机手感（速度/灵敏度） |

## 实现说明（给维护者）

- **相机**：客户端构造不加入世界的 `EntityLivingBase`（1.7.10 的 `renderViewEntity` 字段类型
  要求），每 tick 写姿态、原版渲染自动插值。服务端不存相机状态（玩家不动，锚点=玩家位置），
  只按「目标在玩家半径内」校验。
- **手臂隐藏**：GTNH Forge 反向移植的 `RenderHandEvent`（`RtsHandHider`，EFR 旁观同款）——
  原版 `ItemRenderer` 画手只看 `mc.thePlayer`，换相机实体藏不住手。
- **输入契约**：`GuiScreen.handleInput()` 外层已按事件循环调用 `handleMouseInput()`，
  覆写必须只处理「当前事件」（1.3.0 在覆写里再套 `while (Mouse.next())` 导致每 tick
  第一个鼠标事件必丢——滚轮/单击失效的根因）；lwjgl3ify 下 `getEventDWheel()` 一格 ±1
  （非 LWJGL2 的 ±120），归一化做了双兼容。
- **远程互动**：`TemporaryContextSwitcher` 把玩家临时摆到目标旁 4 格走原版交互逻辑再传回
  （不发同步包），GT 机器等第三方方块零适配成本。
- **远程 GUI**：mixin 放宽 `EntityPlayerMP.onUpdate` / `EntityPlayer.onUpdate` 两处每 tick
  `canInteractWith` 距离检查（只对本模组远程打开的容器生效）。
- **批量**：参数（形状/填充/角点）两端共用 `ShapeGenerator` 生成坐标，服务端权威；
  Job 按 tick 预算推进（照 `LocatorManager` 的模式），玩家下线即取消。
- **网络**：discriminator 11~17，全部「只发意图」。
- 相机实体不吃疾跑/飞行/濒死的 FOV 修正，反投影射线计算直接用 `fovSetting`，
  与画面所见一致（`RtsCursorPicker`）。

**不依赖** Et-Futurum-Requiem / Hodgepodge：RTS Building 原版实现就不基于观察者模式；
Hodgepodge 的粒子朝向修复（`fixCameraParticleRotation`，默认开）对相机分离场景是被动受益。
