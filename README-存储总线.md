# 共享存储总线

> 把**一个相邻容器**接进全服共享背包，让它在共享终端里像仓库的一部分一样出现、存取。
> 配置语义对齐 **AE2 的 ME 存储总线**：优先级、访问模式、筛选、物品与流体。

---

## 它解决什么问题

共享背包本身是一个**没有位置**的池子。现实里总有一些东西已经在箱子里、在机器的输出仓里、
在储罐里，不可能为了用共享终端访问而全部搬进池子。存储总线就是那个「接口」：

- 箱子里的东西**立刻出现在共享终端的库存列表里**（和池子里的同种物品合并计数）；
- 从终端取东西时，按优先级从总线对应的容器里拿；
- 往共享背包放东西时，按优先级先填总线对应的容器，剩下的才进池子；
- AE 共享背包元件、IO 节点、GT 管道看到的也是同一份聚合库存。

它和 **IO 节点**的区别：IO 节点是「每隔几 tick 主动搬一次」，总线是**按需、就在库存里**；
总线的容器内容不会先被搬进池子，取的时候才真的从容器里拿。

## 合成与放置

```
     末影珍珠
 铁锭  箱子  铁锭
 铁锭  漏斗  铁锭
```

用矿物词典（`enderpearl` / `ingotIron` / `chestWood`），装了别的模组也成立。
`enableRecipe=false` 时和其它配方一起关闭。

**放置**：拿着总线右键一个方块的面，总线就放在那个面外侧，并把**被右击的那个方块**
当成目标容器。目标面暂时不是容器也能放下（GUI 会显示「没有可访问的容器」），
不再自动换到别的相邻面。右键时不用潜行；潜行也照样会贴/加面。

**一个格子最多六条**，每条贴一个面、各自独立：

- 第一次右键任意方块面放下方块；之后拿着总线右键**另一个相邻方块的面**（不是右键已经
  放好的薄板），会先找这个方块周围已有的总线格，再把新的一条加到那个格子朝向它的面，
  不再占第二个方块位置；右键这个方块的**任意一面**都可以。
  目标面暂时不是容器也允许先贴（GUI 显示未接容器），以后那里放了容器会自动接上。
- **放置/加面不会自动打开 GUI**（和 AE 部件一致）；要配置某一条，右键它对应的面板。
- 手持总线、视线对准会放置/加面的位置时，客户端会画出**白色三层线框**（参考 AE
  PartPlacement 的放置预览）；没有可放置面时不画。
- 右键某一块板打开的是**那一条**总线的界面；界面里 `←` / `→` 在已安装的面之间切换，
  每条的优先级、访问模式和筛选互不影响；
- 左键点某一面的板只拆下那一条（掉落一个总线物品），拆掉最后一条才移除方块；
  总线方块本身**不能被普通挖掘整块拆掉**，生存和创造模式都是逐面左键拆除。
  只有爆炸、命令等外部破坏才会把剩余的面一起掉落。

外形细节：

- 每条是**贴在目标容器表面的 AE 风格阶梯面板**：仍占目标旁边的一格空气，但只渲染/碰撞
  朝向目标的三层结构（10×10 底板、12×12 中层、6×6×2 凸起接口，整体 4 像素深），
  其余空间可以通行；不是满方块。
- 因为板贴在目标那一面，那一面的右键会优先打开对应总线的界面；板边缘和其它面仍可正常
  操作目标容器。不拿总线时潜行右键会让路给 GT 扳手；拿着总线时潜行则正常贴/加面。
- 目标可以是箱子、桶、GT 机器、输入/输出总线、储罐、其它模组的 `IInventory` /
  `IFluidHandler`；
- **不能**是共享终端、IO 节点或另一条存储总线（会递归）。

## 界面

右键总线打开。所有改动都是**服务端权威**：界面改完立刻整份发给服务端，服务端回一份
权威值覆盖本地，客户端不做本地预测。

| 区域 | 作用 |
| --- | --- |
| **总线面** | 当前正在编辑哪一条总线；`←` / `→` 在已安装的面之间切换；下方显示该面目标方块的注册名和「物品 / 流体 / 都有 / 没有容器」 |
| **访问** | `读写`（默认）/ `只读` / `只写`，见下表 |
| **筛选** | `白名单` / `黑名单`；右边是 `精确` / `模糊` / `矿辞` 三种匹配方式 |
| **优先级** | `-` / `+`；按住 Shift 一次 10 点。范围 ±1,000,000 |
| **物品筛选 / 流体筛选** | 各 9 格。左键拿着物品（或装满的桶/单元、GT 流体显示物品）点格子设置；空手或右键点格子清除 |
| **清空筛选** | 清掉两类筛选的全部 9 格 |
| **完成** | 关界面（配置已经逐次提交） |

> **筛选格子不消耗光标上的东西。** 它只是把「这个条目」记下来；右键清除、空手清除都不会
> 把光标物品放进容器。流体筛选用「装满的桶 / 单元」或 GT 的流体显示物品来设置。

### 访问模式

| 模式 | 共享终端 / AE 能看见 | 能取出 | 能写入 |
| --- | --- | --- | --- |
| **读写**（默认） | 是 | 是 | 是 |
| **只读** | 是 | 是 | 否（写入落到池子） |
| **只写** | 否 | 否 | 是（隐藏库存仍计入存量上限） |

只写适合「只进不出的缓存箱」；只读适合「把成品箱暴露给终端，但不让自动化往里灌」。

### 优先级

语义和 AE 存储总线一致：**写入时高优先级先填，抽取时低优先级先抽**。
共享存储池本身按优先级 **0** 处理。

| 优先级 | 写入顺序 | 抽取顺序 | 典型用途 |
| --- | --- | --- | --- |
| `> 0` | 最先 | 池子之后 | 缓冲区：新东西先进箱子，池子当后备 |
| `0` | 池子之前（同优先级按登记顺序） | 池子之后 | 和一个普通箱子差不多；池子有货时先抽池子 |
| `< 0` | 池子之后 | 最先 | 「先掏空这个箱子」：终端取东西会先拿它 |

> 因为共享池是无限的，**负优先级总线在正常写入时几乎收不到东西**（池子永远收得下）。
> 它的价值在抽取侧：把要优先消耗的库存放在那里。往里面放东西请手动放或单独配 IO 节点。
> 这条行为和 AE 网络里「低优先级存储最后才填」是一致的，只是这里的 0 号存储无限大。

### 筛选与匹配

- **空白名单 = 全部允许；空黑名单 = 全部允许。**
- 白名单：只有列出的条目能通过；黑名单：列出的条目被拒绝。
- 匹配方式：
  - **精确**：物品 + 元数据 + NBT 完全一致（和共享存储的条目键同一套语义）；
  - **模糊**：只看物品 + 元数据，忽略 NBT（受损工具、不同电池电量等会一起匹配）；
  - **矿辞**：按矿物词典名相交匹配（物品侧）。流体没有矿辞，这一档对流体等价于精确。
- 筛选同时约束「显示/取出」和「写入」；被筛掉的条目不会出现在共享终端里，也不会被总线写入。
  因此它们也不计入共享存储的存量上限 —— 对总线来说，它们根本不存在。

### 存量上限

共享存储的按条目上限仍然生效，而且算的是**池子 + 所有总线（包括只写总线的隐藏库存）**：

- 自动化写入到上限就停，剩下的部分由调用方处理；
- 手动存入仍然可以超出上限；
- 设置上限不会删除任何东西，包括总线容器里的东西。

## 和 AE 存储总线的对应关系

| AE2 ME 存储总线 | 本模组共享存储总线 |
| --- | --- |
| 贴在容器上的线缆部件 | 贴在目标容器表面的 AE 风格三层阶梯方块（底板 10×10、中层 12×12、接口 6×6×2）；多面掩码由方块实体描述包同步，初始目标面存在 metadata 里 |
| 模型材质 | 三层盒子尺寸取自 AE2 `PartStorageBus#getBoxes`；渲染时直接引用 AE2 的 `PartStorageSides` / `ItemPart.StorageBus` 图标，不复制资源 |
| 优先级 | 同语义，池子按 0 |
| 读 / 写 / 只读 / 只写 | `读写` / `只读` / `只写` |
| 9 格过滤 + 容量卡扩容 | 物品 9 格 + 流体 9 格，不占升级卡 |
| 模糊卡 / 反相卡 / 矿辞卡 | 界面里的 `精确 / 模糊 / 矿辞` + `白名单 / 黑名单` 开关 |
| 物品（基础 AE2） | 物品 + 流体都支持 |
| 需要通道 / 电力 | 不需要（共享存储本身不是 ME 网络） |
| 分区（Partitioned）/ 粘性等 | 未实现 |

## 技术说明（开发者向）

- **聚合方式**：`StorageBusRegistry` 维护「可读」和「全部」两张聚合表；`SharedStorage` 的
  `getItemAmount` / `snapshotItems` / `getItemTotal` / 存量上限计算都把它们并进来。
  总线内容不写进共享存储的存档文件，它们本来就在各自容器的方块实体里。
- **写入路由**：`SharedStorage.insertItem` 先走优先级 ≥ 0 的总线，再进池子，最后才走
  优先级 < 0 的总线；抽取反过来（负优先级 → 池子 → 非负优先级）。
- **守恒**：
  - 写入按目标容器**实际增加的数量**记账（读回槽位核对），不接受「收下调用但不改内容」；
  - 抽取按源格**实际减少的数量**记账，`decrStackSize` 返回的栈只作为上限参考；
  - 主动 IO（IO 节点 / 共享终端的面配置）从容器抽入时走 `insertItemDirect`，直接进池子，
    避免「源容器本身挂着总线 → 抽出来又被写回同一个箱子」的循环；
  - 主动输出走 `extractItemDirect`，只从池子取，避免把总线容器里的东西又推回它自己。
- **刷新**：总线每 `storageBusRefreshTicks`（默认 10 tick）扫描一次目标，玩家打开共享终端时
  额外刷新一次。扫描结果变化会推进聚合版本号，终端 / AE 的快照缓存随之失效。
- **加载生命周期**：区块加载后的第一个 tick 登记，区块卸载 / 方块拆除时注销。总线的目标容器
  和总线本身都要在已加载区块里；区块卸载后它的库存会暂时从共享存储里消失（和 AE 一致）。
- **网络**：`PacketStorageBusSync`（S2C，#34，配置 + 目标信息）、
  `PacketStorageBusConfig`（C2S，#35，整份上行 / 权威值请求）。服务端校验：必须开着这条
  总线的界面、8 格内、容器里装的就是这条总线；配置里的枚举和数字全部夹回合法值。
- **配置**：`enableStorageBus`（默认开）、`storageBusRefreshTicks`（1..200，默认 10）。
- **回归检查**：`gradlew.bat verifyStorageBus`，覆盖聚合、优先级、只读/只写、筛选、矿辞、
  模糊、流体、注销与直接池入口。

### 已知限制

- 一个格子最多六条总线，分别贴六个面；同一面只能有一条。每条只接一个目标容器，
  不提供「把多个面合并成一条统计」的模式。**同一个方块只能占据一格的一个方向**：
  想让一个格子有多个面，它的多个方向必须各挨着一个方块（可以是同一个大机器的不同方块）。
- 薄板仍占目标旁边的一格空气：那一格必须能放方块，每条板覆盖目标的那一面；不能和管道、
  覆盖板或另一个方块共用这一格。
- 筛选格子不支持 NEI 拖入（需要手上拿着物品/流体容器点）。
- 没有 AE 的容量卡、分区、粘性等高级模式。
- **哪些面有总线由方块实体的描述包同步**（metadata 只有 4 位，装不下 6 位掩码），
  客户端渲染/碰撞读这份掩码；旧存档的单面 `bus` NBT 会自动迁移成对应面的一条。
- **`/futashared clear` 只清共享存储池，不动总线接进来的容器**：总线内容住在玩家自己的
  箱子里，管理员清库不应该顺手删掉它们。
- 总线自己的方块实体不保存库存，只保存配置；拆掉总线不会删除目标容器里的东西。
- **IO 节点 / 共享终端的「主动输出」只从共享存储池取料**，不会把总线容器里的东西再推给
  另一个相邻容器（否则输出目标正好是同一个总线容器时会出现无意义的来回搬运）。
  总线内容仍然可以被共享终端、AE 网络和玩家直接取用；需要自动外送时，让目标机器自己
  从总线容器抽，或者用 IO 节点从池子取。
