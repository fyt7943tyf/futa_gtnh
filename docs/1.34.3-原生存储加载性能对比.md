# 1.34.3 原生存储加载优化与性能对比

本轮继续优化 1.34.2 原生公共 AE 的加载成本。存储介质、原生 `CellInventory`、存档格式和迁移协议不变。没有以跳过检查、延迟解码或独立数量缓存换取成绩。

## 实现

- 新资源登记直接查询身份表，命中后刷新正缓存；未命中时只构造一份私有身份，取消先构造负缓存身份再立刻重复构造的步骤。位置仍按资源增量维护，数量仍读原生元件。
- 缺失内容检查使用与原版 `ItemStack` / Forge `FluidStack` 解码器相同的注册表判空条件（物品短 ID、流体注册名），不再仅为判空而构造和内部化一个 AE 栈。随后仍由真实原生元件解码完整物品、流体及 NBT。
- 从 AE 栈生成 `ItemKey` / `FluidKey` 时直接取独立 NBT 副本，省去“临时原版/Forge 栈 → 再复制 NBT”的中间步骤。空标签归一化、完整身份、哈希、未注册流体拒收及调用方可变对象隔离继续生效。私有 AE 身份仍重新创建，避免 `AEItemStack.copy()` 共享可变定义。
- 保留类型数、正数量、逐项求和、`long` 溢出和总计核对；包括额外 `#...` 字段在内的缺失内容仍隔离整枚元件并保存原始 NBT。旧迁移的源文件/备份摘要、UUID、重挂载逐键核对和原子所有权提交均未修改。

## 配对加载测试

环境：macOS aarch64，JDK 17.0.20.1，2 GiB 堆；AE rv3-beta-1082-GTNH / AE2FC 1.5.108-gtnh，真实 `ApiStorage`。每通道 1、63、1024、4096 种资源，每种 100 万，分别测试无 NBT 的元数据物品/独立流体和带 NBT 的物品/流体。

优化前使用 v1.34.2（ad361c30006b2ea14cbee92cd5f5928d98a3d459）冻结源码，仅改类名。三个测试臂使用完全相同的元件 NBT 和压缩字节，挂载返回前均已完整解码原生内容。公共臂包含计数校验、缺失模组检查及完整资源索引；普通 AE 直接挂载同种真实 Universe 元件。

每个负载启用三个独立 JVM；每项每臂预热 20 次、采样 60 次，轮转执行顺序。表格为三个进程 P50 的中位数，单位 ms。逐键数量/完整 NBT 核对在计时外完成；六轮共通过 155574 项断言。小规模耗时接近噪声区，不解释为稳定收益。

该项只计元件阵列，三臂读取同一份压缩数据；不包括公共服务元数据和迁移源备份验证，后者在下方完整路径单列。

| 负载 | 每通道种类 | 1.34.2 公共 AE | 1.34.3 公共 AE | 普通 AE |

| nbt | 1024 | 4.6379 | 3.7898 | 2.4039 |

8192 种资源中，NBT 负载从 18.94 ms 降至 15.46 ms，减少约 18.4%；无 NBT 从 11.22 ms 降至 10.34 ms，减少约 7.8%。普通 AE 分别为 10.05 ms、6.85 ms。**加载仍有公共资源索引与完整性保护的额外成本，尚未完全等同普通 AE。**

## 完整路径复测

另各启一个独立进程运行原有四臂完整基准，每通道 4096 种。以下为各负载单进程 P50，不与上面的三进程配对表混算，也不将上一版报告中不同包装路径的数值当作精确配对基线。保存/加载各预热 12 次、采样 50 次；存取预热 300 次、采样 600 次。两轮共通过 434208 项数量、缓存和 NBT 断言。

| 负载 | 操作 | 旧共享池 | 1.34.3 公共 AE | 普通 AE |
| --- | --- | ---: | ---: | ---: |
| plain | 序列化＋gzip ms | 26.660 | 69.018 | 68.891 |
| plain | 解压＋完整数据加载 ms | 2.806 | 10.055 | 6.895 |
| plain | 随机物品＋流体取出并放回 µs | 3.417 | 50.500 | 57.083 |
| nbt | 序列化＋gzip ms | 52.774 | 96.178 | 96.517 |
| nbt | 解压＋完整数据加载 ms | 4.576 | 17.397 | 11.452 |
| nbt | 随机物品＋流体取出并放回 µs | 9.167 | 71.916 | 67.875 |

公共完整加载包括 `NativeMeStorageData` 版本/UUID/迁移元数据检查、服务元数据读取及绑定。普通 AE 为完整元件 NBT 解压和原生内容挂载；旧共享池为旧独立账本，不提供等价原生盘结构。随机混合一次包含物品/流体各取一次、放回一次，四个真实网络请求。

单次真实磁盘迁移观测（每负载一次，非稳定上限）：

| 负载 | 完整旧服迁移 ms | 已迁移存档来源校验＋加载 ms |
| --- | ---: | ---: |
| plain | 92.709 | 10.992 |
| nbt | 146.201 | 19.177 |

迁移测试实际执行备份、SHA-256、fsync、转换、持久化重读核对及原子所有权提交；重启继续验证原始来源摘要。普通 AE 没有旧共享池迁移，未给它虚构对应迁移耗时。

## 正确性与兼容验证

- `spotlessApply build spotlessCheck` 通过。原生索引/加载回归 32481 项，其中新增 250 项；独立随机库存模型、正常请求不全盘扫描、模拟、限额/托管、近 long 上限及旧句柄失效继续通过。
- 新增冻结/优化加载器配对覆盖正常存档、缺失物品/流体、物品/流体总计不符、负数量、缺行、类型超限、数量溢出、负总计、旧小写流体标签和额外缺失行。检查源 NBT 未变、整枚隔离 NBT 一致、再次重挂载不重入不丢量。新增原生键转换验证嵌套列表、复合标签、字节/整数数组、哈希与可变请求隔离。
- 原有 46 项迁移测试和产线/IO 统计回归通过。新的两种保存负载均在独立进程逐键重载验证。源备份、UUID、限额、未决托管及失败保护保持原有机制。
- 数据格式仍是原生元件版本 1；既有 1.34.0–1.34.2 原生数据直接加载，不重新导入旧池；更早旧共享存档沿用自动迁移。网络协议/绑定/历史归属规则未改变。
- 真实客户端/集成服务端验证结果见 [交付说明](1.34.3-改动与交付说明.md)。测试仅使用隔离开发存档。

```sh
./gradlew benchmarkStorageBackends -PstorageVerifySaved=true -PstorageScales=4096 -PstorageProfile=plain --offline --console=plain
./gradlew benchmarkStorageBackends -PstorageVerifySaved=true -PstorageScales=4096 -PstorageProfile=nbt --offline --console=plain
```
