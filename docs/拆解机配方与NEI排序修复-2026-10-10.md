# 拆解机工作台配方与 NEI 排序修复

基于当前远端 `main` 的 `9495199`，按用户要求发布 **1.27.13**。隔离工作分支 `codex/disassembler-crafting`，修复提交至远端 main。原 `futa_gtnh` 检出的 1.23.2 和此前未提交的矿辞修复保持原状。

## 原因及处理

- 原工作台白名单使用精确类名，排除了 GTNH 核心模组的 `ShapedUniversalRecipe` / `ShapelessUniversalRecipe`。用户 1.27.11 的目录报告中有 4,521 条有序 Universal 路线因此跳过。这两个类的真实 `getInput()` 覆盖父类占位输入，成品为静态拷贝；已核对用户安装的 NHCore 2.9.71 字节码，现单独支持这两个类型，保留其它未知自定义类的排除规则。
- 1.27.11 / 当前 main 仍使用 `uniqueIngredient`，不同矿辞候选全部被视为冲突；此前本地矿辞统一返还修复未进入这些版本。本次合并该修复：材料按 GT 明确标准统一，ULV 至 LuV 电路返还对应基础电路；候选数量、共同矿辞、目标属于候选的检查保留。组装机及装配线使用同一规则。
- 参考 [GTNL 微光](https://github.com/ABKQPO/GT-Not-Leisure/blob/dev-290/src/main/java/com/science/gtnl/utils/recipes/ReversedRecipeRegistry.java) 的反向工作台规则，以及 [GT reverseShapedRecipe](https://github.com/GTNewHorizons/GT5-Unofficial/blob/5.09.54.175/src/main/java/gregtech/api/util/GTUtility.java)：锤子、扳手等合成工具参与合成格匹配，但不列入材料返还。按真实行宽摆放输入，支持完整 3×3 和较小合成格。合成格使用原声明的固定材料，返还才做矿辞统一；避免固定材料归一化后不再匹配原配方。
- NEI 未登记排序时按 0 排列，因而先于有显式排序的 GT 机器。现在在 NEI 配置加载后将拆解类别默认设为 10000；已有自动生成的 0 同样处理，手动非零 overlay/class 排序保留。配方用途、机器催化剂和完整目录入口保留。
- 当前 main 还没有允许拆解 GUI 页码 C2S 请求；一并保留此前获授权的翻页修复和对应回归。

保持单步拆解、固定 32 EU/t / LV 1A / 40 tick、整批原子结算与已有存档格式。动态 NBT、非工具容器输入、无法统一的矿辞、真实多路线材料冲突仍会跳过；并非无条件接受任何自定义工作台配方。

## 当前跳过范围

“动态配方”并非涵盖所有被排除项，具体规则为：

- GT 工作台配方启用 `mKeepingNBT`，或无序配方启用 `overwriteNBT`，直接排除。
- 合成格的实际输出与登记输出的 NBT / 数量不一致，排除；其中也可能有固定附魔或固定初始化 NBT 的静态配方。开发报告中 BartWorks LV/MV/HV Rockcutter 属于这一项。
- 尚未适配的自定义类，例如 IC2 `AdvRecipe`、AE2 `appeng.recipes.game.ShapedRecipe`、龙研 `ShapedOreEnergyRecipe`，按类排除；并不表示这些类里的配方全是动态的。
- 同一成品经统一、聚合和整批约分后，仍有不同的材料、数量、流体或输入批量，按生产路线冲突排除。不选某条路线作为优先返还。
- 没有明确矿辞标准、非工具容器输入、通配材料、概率产出和多个生产输出等，同样排除。

当前采用成品级否决：同一成品任一路线被拒绝，其他可解析路线也会从最终目录移除。这是覆盖率较低的重要原因；本次补齐配方类型及工具处理，不改变该策略。

## 验证

`gradlew.bat build spotlessCheck --offline -I tools/gradle/spotless-cache.init.gradle` 通过，包含 Checkstyle、终端 Shift 点击、共享存储 API、拆解机/背包回归 **241 项**、NEI/UI 回归 **70 项**。

新增断言覆盖九格返还数量、2×2 行宽、真实 GT 3×3 配方中的多个工具候选、固定材料匹配与统一返还分离、容器和未知子类继续排除，以及 NEI 实际分类比较器、生成 CSV 的 0 和非零手动排序。NHCore 测试替身模拟真实的覆盖输入/父类占位行为；测试运行器和替身均不进入发布包。

当前 main 的 `runClient17` 完成真实 GT5U 5.09.54.175 目录扫描和声音引擎启动：12,336 个候选、4,575 条接受配方。LV 研磨机 `gregtech:gt.blockmachines@301` 收录并返还标准 LV 电路及其余材料。开发环境未包含完整 NHCore/333 模组组合；Universal 支持经源码、用户安装 jar 字节码及独立 JVM 回归验证，尚未完成用户完整整合包服务器上的游戏内实测。开发客户端在确认加载后主动终止，Gradle 因测试进程终止记录非零退出。
