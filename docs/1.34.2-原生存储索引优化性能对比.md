# 1.34.2 原生存储增量索引与性能对比

测于 2026-10-27。当前版本只为资源位置维护索引，实际数量继续由 AE2 / AE2FC 原生 `CellInventory` 持有。三处逐次重建已移除：失败请求直接返回；正常数量变化不扫描整盘；迁移批量写入后只为变化的元件统一建索引。

大库存的主要搬运路径已接近原生 AE。不能承诺每个操作耗时完全相等：公共网保留全局数量上限、服务限额、托管和额外加载校验；下表如实保留这些差距。统计边界、媒体 NBT、持久化格式和旧仓库 UUID 未改。

## 测量方法

- 同一 JVM 比较四组：冻结的 `v1.33.10` 旧共享池、冻结的 `v1.34.1` 公共原生阵列、1.34.2 候选阵列、直接挂载同种原生元件的普通 AE。
- 三组原生媒体使用相同 Universe 元件、相同资源、相同数量和请求顺序。每通道 4096 种资源时均有 66 枚元件，共 132 枚；类型上限均为 63。
- 两种负载：`plain` 是无 NBT 的元数据物品与独立流体；`nbt` 是带完整 NBT 的物品/流体变体。每种资源 1000000 件或 mB；两种负载均测每通道 1 / 63 / 1024 / 4096 种，单类型夹具不带 NBT。
- 每种负载 3 个独立 JVM。常规操作每组预热 300 批、采样 600 批，四组顺序交错轮换；表中 P50 是三个进程 P50 的中位数，分配量是三个进程每操作平均分配量的中位数。完整 P95/P99/最大值及 GC 次数在原始 JSON 中。
- 两通道“各取出并放回”包含 4 次真实存取，单通道是 2 次；快速缓存查询用预建 AE 请求，不包含调用端创建原型/NBT 的成本。
- Apple M1 Pro，10 个可用处理器，macOS aarch64，OpenJDK 17.0.20.1+1-LTS，2 GiB 最大堆；AE2 `rv3-beta-1082-GTNH`、AE2FC `1.5.108-gtnh`。
- 本次原生列表工厂使用真实 `appeng.core.api.ApiStorage`，空定义/比较注册表仍采用隔离测试适配。旧 1.34.1 单独报告的适配入口不同，**优化前后数值应以本报告的同进程四组对比为准**。
- 冻结源码只改类名；1.34.1 阵列的一个模式匹配表达式改为等价 Java 8 强制转换。旧提供者固定为已连接状态。三组原生引擎、监视器、网络库存处理器及数量算法是真实依赖实现；没有用哈希表代替原生 AE。
- 源码迭代和游戏验证期间 `version.txt` 保持 1.34.1；本文测试的是 1.34.2 候选改动，发布后才由 Actions 写入新版本。

## 保存和加载

8192 种资源，单位 ms。序列化/压缩及加载各预热 12 次、采样 50 次，三进程 P50 的中位数。媒体与保存格式没有变化，以下比较旧共享池、新版公共 AE 和普通 AE。

加载仍包含公共阵列额外的计数校验、缺失模组检查、不可变兼容键和位置索引；此项比普通 AE 慢。它是加载成本，不应宣传为完全等同原生。保存一项是序列化+gzip CPU，**不是主线程暂停时长**；异步写盘、整世界保存和普通驱动器 Tile/区块保存不在这组计时内。


| 负载 | 操作 | 旧共享池 | 新版公共 AE | 普通 AE |
| --- | --- | --- | --- | --- |
| plain | 序列化 + gzip | 26.584 | 69.454 | 69.420 |
| plain | 解压 + 校验/挂载 | 2.729 | 11.628 | 6.991 |
| nbt | 序列化 + gzip | 52.896 | 97.060 | 97.080 |
| nbt | 解压 + 校验/挂载 | 4.627 | 23.191 | 11.356 |

## 实现及正确性

- 资源位置按完整身份增量维护，数量始终查询原生媒体。数量变化保留位置；资源出现/耗空才添加/移除所属元件，不建立独立数量镜像。
- 固定每通道一项的查找缓存仅保留私有身份，并以结构代数失效；不引用调用方可变请求作为缓存键。负缓存、耗空后补回、NBT 变化及清空/重挂载均验证。
- 正常及模拟请求不全盘枚举；失败请求不更新索引。空闲容量集合帮助兼容直写和迁移跳过满盘，批量完成后每个变化元件只扫描一次。
- 原生集成主动解包后直接写入 `CellInventory` 时，通过其保存回调修复那一枚元件；异常修复也是局部回退。这种没有具体资源参数的路径需要扫描该盘，不能宣称所有内部访问都零成本。正常受控存取不走此回退。
- 保留服务限额、托管预留和聚合 `long` 上限。分配器只处理新增容量，模拟时扣除既有元件能提供的容量，避免部分限额容量被重复报告。
- 旧解码器只在物品、流体两通道全部成功后清空旧内存表；拒收、溢出或中途失败保留整个旧解码器。原有原始文件、专用备份、校验重挂载及原子所有权提交继续生效。1.34.0/1.34.1 原生存档只重建内存索引，不重新导入旧共享池。

新增 32231 项真实引擎回归通过，包括独立随机模型、完整 NBT、跨多盘近 `Long.MAX_VALUE`、空请求、限额/托管、模拟、原生内部写入、可变请求、旧句柄失效、失败迁移保留源表，以及通过拦截 `getAvailableItems` 证明正常存取不枚举整盘。原有 46 项迁移、103306 项统计优化及完整 build/Spotless 回归通过。


六轮性能测试另通过 1648878 次逐键/数量断言（每轮 274813 次，包含重复资源核对）；两种负载的保存文件在独立进程中各通过 31120 项重挂载/缓存命中检查。

真实 `runClient17 -PuiSmoke` 验证：

- `run/incremental-native-index-client`：旧共享文件、长数量/NBT、原 UUID、限额及托管自动迁移；真实取料并保存/重挂载，原始旧文件字节不变。
- `run/query-optimization-client`：直接加载此前 1.34.1 开发存档；已消耗资源没有复活，UUID 不变，保存、重新加载及坏版本保护通过。
- 两套均通过公共 ME、跨维度普通盘、手持产线终端、二合一接口双总线正常/优化取料、零库存历史与实际 56 件/12000 mB 统计，以及 26 个 GL 页面。未操作生产服。

## 复现和限制

```sh
./gradlew benchmarkStorageBackends -PstorageProfile=plain --offline --console=plain
./gradlew benchmarkStorageBackends -PstorageProfile=nbt --offline --console=plain
./gradlew benchmarkStorageBackends -PstorageVerifySaved=true --offline --console=plain
./gradlew benchmarkStorageBackends -PstorageProfile=plain -PstorageVerifySaved=true --offline --console=plain
```

每次命令是一个独立 JVM，正式报告每种负载各重复三次。结果写到 `build/reports/storage-backend-benchmark.json`，每轮需另存。测试工具、冻结基线和注册表适配不进入发布 JAR。

不包含物理驱动器/线缆/机器 tick、能源/频道、在线玩家监听、网络传输、外接库存与原料统计开销；不能换算整服 TPS。未给出新类型在线扩容拓扑的稳定分布，也未测单种资源接近数量上限造成跨多盘时的吞吐；该情况的数量安全由回归覆盖。加载比普通 AE 慢的差距已保留，不能承诺各方面完全相同。
