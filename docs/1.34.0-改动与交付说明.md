# 1.34.0 改动与交付说明

共享背包现在作为公共 ME 的随身访问入口，实际库存全部由原生 AE2 / AE2FC 存储元件承载，移除运行时的旧共享池存储提供者及定时保存流程。

## 原生存储与自动扩容

- 直接使用已注册的原生 Universe 物品、流体元件及 AE 的 `CellInventory`。每枚元件的物品 NBT 就是其实际库存，可以独立由原生 AE 读取。
- 元件达到容量或类型限制后自动增加下一枚，保留无需维护的无限容量体验；每种资源仍使用 `long` 数量，最多 `Long.MAX_VALUE`，类型数没有固定盘位上限。
- 随身 B 键、共享终端、共享 IO、全服共享、跨维度、公共接入器、产线统计及已有设备绑定继续使用同一个公共 ME 网。旧“共享背包元件”保留为兼容访问入口，不再持有独立库存。
- 库存随 Minecraft 世界数据保存，取消旧共享库存的定时写盘与“共享存储已保存”日志。显式保存和重载兼容 Hodgepodge 异步写入，先完成已排队的写盘。

## 自动迁移与兼容

- 首次启动先验证旧共享文件，建立完整原始备份并校验 SHA-256，再迁入原生元件。序列化后重新挂载，逐项核对数量、NBT 与服务元数据，通过后才提交迁移所有权。
- 原有仓库 UUID、超出旧限额的库存、限额设置、未知条目和未决合成/IO 托管保留；外接 ME 盘和外部容器不复制。已有产线无需重绑。
- 重启只加载当前原生元件，禁止重新导入已归档旧库存；缺失或损坏的原生文件不能被空仓库或旧快照替代。中断提交可校验续接。
- 原生 AE 无法安全接收的条目会停止迁移，保留源文件与备份；不跳过或销毁。缺失模组的原生元件保留整盘原始 NBT，恢复模组后再挂载。
- 客户端、服务端建议同时更新到 **1.34.0**。网络协议及终端操作保持兼容，库存持久化后端已改变；AE2 与 AE2FC 都是必需前置，原生 Universe 元件需启用。
- 回滚需要恢复完整世界备份，不能只降级模组或恢复旧共享文件。旧库存文件不再是当前库存；详细文件与恢复边界见 [迁移说明](public-me-migration.md)。

## 验证

- `./gradlew spotlessApply build spotlessCheck --offline --console=plain` 通过。
- 46 项原生媒体/迁移回归通过，使用真实 AE2、AE2FC 元件与 `CellInventory`，覆盖近 `Long.MAX_VALUE` 数量、NBT、类型扩容、模拟、限额、拒收、失效句柄、中断、坏文件、未知条目与旧版本防误读。
- 真实客户端与集成服务端验证上一版共享文件和 UUID 升级，原始物品 4,294,967,311 件、流体 27,000,000,013 mB 中分别保留 3 件和 5 mB 未决托管，迁移后真实消耗 101 件和 203 mB，经正常世界保存、重载与重启核对数量和 NBT。旧库存文件保持原始字节。
- 原有公共 ME、跨维度、普通外接盘、二合一接口双总线流速和产线终端检查继续通过；26 个真实 GL 页面通过。
- 测试只修改严格命名的隔离开发存档，不操作生产服务器；测试夹具不打入发布 JAR。
