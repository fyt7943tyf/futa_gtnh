# 1.33.0 迅步作物与植物魔法加速

## 使用变化

- 迅步增加“加速”页：CropsNH 空双架的繁殖/杂交独立开关、独立强度，植物魔法独立强度。半径仍与生长页共用。
- 杂交默认关闭。旧迅步保留原来的作物设置，植物魔法强度在首次单独设置前沿用旧生长强度；新杂交强度默认最多 20 次/5 秒。
- 强度表示每 100 个服务器刻度追加的原生工作次数，均匀分散执行。植物魔法在不触及预算、原对象允许每次调用工作时，总工作频率最高约为原来的 11 倍。
- 加速页每秒显示服务端探测目标、最近执行/跳过次数和预算限流状态。界面需要佩戴迅步并开启至少一种植物光环才有状态数据。

## CropsNH 与 Agricarnation

- 植株调用原生生长入口，保留水、肥料消耗以及光照、底矿、土壤、生长条件。成熟、生病、条件不满足或生长率不为正时不追加生长。
- 空双架调用原生杂交入口，保留父本成熟阈值、概率、配方、三维继承和底矿要求。机器专属配方仍需机器完成。
- 额外杂交不会同时调用空架的杂草生成逻辑；自然杂草机制仍按原模组运行。
- 植物魔法 Agricarnation 及其迷你变体能够识别 CropsNH/IC2 作物架，并推进原生生长。保留其随机选点、范围、红石和每次 5 mana 的原有流程，不为其增加空架杂交能力。

## 性能与公平调度

- 球形范围从近到远渐进发现，作物每名玩家每刻最多检查 512 格；全维度所有发现任务共用 2048 次检查额度。放置事件会主动发现附近新目标，周期扫描兜底。
- 植物魔法通过有上限的增量扫描发现已加载实体/方块实体，缓存只持有弱引用。
- 所有植物光环共用每维度每刻最多 4096 次额外调用，以及默认 3 ms 的软时间预算。配置 `swiftStep.swiftStepAuraBudgetMillis` 可设 0 关闭时间限额，次数限额始终存在。单次原生调用不能中途打断，软预算不保证严格的耗时上界。
- 玩家顺序、作物目标、植物魔法实体与方块实体轮换；作物与植物魔法轮换优先顺序。重叠同类光环按覆盖该目标的最高强度计算，不按人数叠加。
- 离开范围和卸载区块立即停止额外调用；换维度、离线、卸载世界、关闭服务端清理缓存。不强制加载区块，不积攒欠账突发补做。
- 首次进入最大范围需要若干刻发现目标；扫描和限流会使实际效果低于设定上限。依赖世界时间的内部冷却、外部物流、魔力供应等仍可能限制产量。

## 兼容与验证

客户端和服务端需要一起更新。设置包保留旧字段前缀并附加新字段；旧物品 NBT 兼容迁移，但新增状态包需要双方新版。

回归入口 `verifyBotaniaAura` 通过实际 LaunchWrapper/Mixin 加载生产 Agricarnation 注入，使用真实 Botania 1.13.36-GTNH 与 CropsNH 2.0.133 的工作方法验证生长、原生资源消耗、杂交概率、三维继承、底矿、机器配方限制、白雏菊、魔力池、火花、预算、重叠、范围、卸载和界面控件布局。

发布前执行 `gradlew build spotlessCheck`。这些是内存世界与真实类回归，不是完整 GTNH 存档的实机 TPS 基准；实际大型农场的收益需在对应服务器负载下观察。

构建同时修复 Eclipse 4.19 格式化器旧更新站返回 HTTP 200 停机页面的问题，改用同版本官方固定发布仓库；保留原来的导入顺序和格式规则。
