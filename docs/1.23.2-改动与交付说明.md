# futa_gtnh 1.23.2 改动与交付说明

日期：2026-10-03。修复用户提供的 1.23.1 客户端日志中两项拆解机 UI 故障，并按后续要求加入矿辞统一返还。1.23.2 尚未推送，本次沿用该版本号重新构建。

## 修复

- 机器 GUI 翻页：页码 `IntSyncValue` 原先没有启用 `allowC2S`，点击翻页时 Modular UI 2 拒绝发送请求并在聊天区报错。现在物品/流体页码允许客户端请求，服务端继续校验页码范围，进度仍只由服务端同步。
- NEI 查看配方：自绘背景没有使用纹理，但 NEI 的继承前景绘制仍会绑定 `getGuiTexture()`。原来的空字符串被解释为 `minecraft:`，图片解码为空，引起客户端 `Registering texture` 崩溃。现在返回实际存在的原版库存纹理；原有自绘背景和配方内容保留。
- 补齐 NEI `loadTransferRects` 配方组入口，消除日志中的 catalyst handler 缺失提示，通过拆解机物品可以进入全部拆解配方。
- 矿辞统一返还：按所有候选共同的 GT 材料/形态矿辞查找指定标准物品；ULV 至 LuV 电路使用对应等级的 GT 基础电路，更高等级要求 GT 存在指定目标。不使用候选列表首项或矿辞首项作为兜底。标准物品必须属于配方候选，候选数量必须相同；NBT、通配符、容器、不明类别及多个矿辞目标不一致时继续跳过。固定的材料输入同样归一化，使工作台、组装机及装配线的等价路线能够合并，真实材料/数量/流体冲突仍然阻止拆解。
- 配方报告列出接受配方的实际物品返还清单，以及无法统一时的候选物品；机器说明明确提示矿辞返还标准物品。

翻页修复需要客户端和服务端均更新为本次重新构建的 1.23.2：旧服务端仍不允许客户端页码请求。拆解目录以服务端为准，两端更新可使 NEI 返还清单保持一致。MTE ID、槽位编号、网络包和存档格式兼容原版本；已开始的任务继续按存档中的产物结算，空闲机器使用新目录。未改变固定 32 EU/t、1A、40 tick 和单步拆解。

## 验证

`gradlew.bat build spotlessCheck --offline -I tools/gradle/spotless-cache.init.gradle` 通过。包括 Checkstyle、终端 Shift 点击、共享存储只读 API、拆解机/主背包转移 227 项断言及 `verifyDisassemblerUi` 66 项断言。矿辞回归使用真实 Forge 注册表和 GT 指定标准，覆盖顺序独立、数量一致、原配方不变、零数量催化剂、未知材料、NBT、通配符、候选外目标、电路基础返还、多个矿辞标准冲突、等价路线合并、真实冲突继续阻止，以及 40 tick 完成一次结算。

新增测试构造实际客户端/服务端拆解机 UI，验证物品与流体三页输出的 C2S 权限、页码序列化/服务端应用、可访问页面及越界请求。执行实际 NEI `TemplateRecipeHandler.drawForeground`，验证绑定的资源可以解码为图片并继续绘制配方说明；仅替换 GL 状态调用、字体绘制和设备传输。测试运行器不进入发布 jar。

已读取用户安装的 Modular UI 2 2.3.91 的字节码，确认权限开关与开发依赖 2.3.89 一致；NEI 版本均为 2.8.144-GTNH。`runClient17` 完成开发环境 73 个模组加载及声音引擎启动。未完成用户完整 333 模组环境中的服务器联机实测，界面交互验证使用上述独立 JVM 回归。

矿辞修复后的 `runClient17` 完成真实 GT5U 5.09.54.175 配方目录扫描：12,255 个候选、4,566 条接受配方。LV 研磨机（`gregtech:gt.blockmachines@301`）由 `SKIP ... Conflicting ore alternatives` 变为 `ACCEPT`，返还 LV 活塞 1 个、LV 马达 1 个、钻石 1 个、电缆 3 条、LV 外壳 1 个、标准 LV 电路 2 个。原用户环境中的 GT5U 5.09.54.174 提供同样的归一化 API；尚未在该完整整合包服务器上实测。
