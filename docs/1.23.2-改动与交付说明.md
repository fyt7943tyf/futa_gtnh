# futa_gtnh 1.23.2 改动与交付说明

日期：2026-10-03。修复用户提供的 1.23.1 客户端日志中两项拆解机 UI 故障。

## 修复

- 机器 GUI 翻页：页码 `IntSyncValue` 原先没有启用 `allowC2S`，点击翻页时 Modular UI 2 拒绝发送请求并在聊天区报错。现在物品/流体页码允许客户端请求，服务端继续校验页码范围，进度仍只由服务端同步。
- NEI 查看配方：自绘背景没有使用纹理，但 NEI 的继承前景绘制仍会绑定 `getGuiTexture()`。原来的空字符串被解释为 `minecraft:`，图片解码为空，引起客户端 `Registering texture` 崩溃。现在返回实际存在的原版库存纹理；原有自绘背景和配方内容保留。
- 补齐 NEI `loadTransferRects` 配方组入口，消除日志中的 catalyst handler 缺失提示，通过拆解机物品可以进入全部拆解配方。

翻页修复需要客户端和服务端均更新为 1.23.2：旧服务端仍不允许客户端页码请求。未修改包结构、MTE ID、机器库存/流体容量、配方算法或存档格式。

## 验证

`gradlew.bat build spotlessCheck --offline -I tools/gradle/spotless-cache.init.gradle` 通过。包括 Checkstyle、终端 Shift 点击、共享存储只读 API、拆解机/主背包转移 208 项断言及新增 `verifyDisassemblerUi` 66 项断言。

新增测试构造实际客户端/服务端拆解机 UI，验证物品与流体三页输出的 C2S 权限、页码序列化/服务端应用、可访问页面及越界请求。执行实际 NEI `TemplateRecipeHandler.drawForeground`，验证绑定的资源可以解码为图片并继续绘制配方说明；仅替换 GL 状态调用、字体绘制和设备传输。测试运行器不进入发布 jar。

已读取用户安装的 Modular UI 2 2.3.91 的字节码，确认权限开关与开发依赖 2.3.89 一致；NEI 版本均为 2.8.144-GTNH。`runClient17` 完成开发环境 73 个模组加载及声音引擎启动。未完成用户完整 333 模组环境中的服务器联机实测，界面交互验证使用上述独立 JVM 回归。
