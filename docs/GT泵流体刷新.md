# GT 泵流体刷新

GT 单方块泵（包括进阶泵）在 `consumeFluid` 中使用 `setBlock(..., air, 0, 2)` 移除流体。标志 `2` 会同步客户端，但不通知邻居。相邻的非源岩浆可能已经转为静止方块，没有待执行的流动更新；即使供给源被抽走、玩家重新登录，它也可能保持流动外观。

## 自动处理

本模组通过 `MixinGTPump` 接入成功移除方块的调用：

- 保留 GT 原来的移除结果、更新标志、耗电和储罐结算。
- 每次成功移除原版水或岩浆后，只检查六个相邻位置。
- 将其中非源的静止水/岩浆转回对应流动方块，保留原来的流体等级，并安排原版延迟更新；已经是流动方块时也会补上更新。
- 不唤醒源方块，不扫描整片岩浆湖，不强制删除流体。仍有源头供给的流动会按原版规则保留。
- 只在服务端执行，跳过未加载的目标或紧邻区块。其它模组的流体保留自身行为。

基于当前依赖 GT5-Unofficial `5.09.54.175` 的实际泵类验证 Mixin。后续升级 GT 应重新运行验证，确认目标方法仍匹配。

## 修复已有残留

安装新 jar 并重启服务端后，管理员站在残留附近执行：

```text
/futafluidrefresh
/futafluidrefresh 32
```

需要 OP 权限等级 2，在游戏内使用。默认半径 16，允许 1–32；范围是以执行时玩家位置为中心的立方体，Y 坐标裁剪到 0–255。每个维度同一时间只接受一个任务，每 tick 最多检查 512 个位置、唤醒 64 个方块，只处理已加载区块。扫描完成会发送消息；岩浆实际消退还需等待原版流体更新，范围内区块应保持加载。

源方块不受指令直接修改。若更新后仍持续流出，应检查上方、侧面及泵范围外的源头。靠近未加载区块边界的方块会跳过，可加载周边后再执行一次。

## 验证与兼容性

`gradlew.bat verifyPumpFluidUpdates` 会验证真实 GT 泵的服务端 Mixin，并在内存世界中运行真实原版流体 tick：重现漏更新、确认无源岩浆/水消退和有源流动保留，检查失败移除、客户端、未加载区块、来源类型、扫描预算及生命周期清理。

本次逻辑无需新网络包，不修改存档格式；随 1.33.3 发布。泵刷新由服务端升级启用，单人游戏安装在客户端后由集成服务端执行。
