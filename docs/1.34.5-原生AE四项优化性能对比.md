# 1.34.5 原生 AE 四项优化与性能对比

完成单次加载注册表结果复用、紧凑元件关联、直接生成兼容池快照，以及容量预留/校验缓冲复用四项改造。存储数量仍仅保存在原生 AE/AE2FC 元件中，格式和迁移流程不变。

## 四项实现

1. 单次同步加载共用注册表查询上下文，最近 ID/名称直接命中，另外最多记忆 64 个结果。不同类型超过预算后关闭字典，仅保留最近值，避免大量不同流体名称导致无收益的缓存增长。上下文在加载返回后丢弃，下一次读取重新查询注册表；缓存的是存在性，不是数量校验结果。
2. 资源直接保存首枚元件引用，仅跨元件时分配额外列表；耗空首枚时按原顺序提升下一枚，仅剩一枚时释放列表。实际数量仍逐枚查询原生元件，近 long 上限、跨多枚及旧句柄保护保持原行为。
3. `SharedStorage.snapshotPoolItems/Fluids` 的原生路径直接生成最终不可变列表及不可变条目，省去中间 `Set<Entry>` 和再次复制。为保留读回调/重入时的遍历安全，继续复制稳定的资源引用集合；不缓存快照数量。离线旧解码器路径保持不变。
4. 加载前以声明类型数估算索引容量，预留最多 16384 个资源、16384 枚元件的初始空间；这仅是有界内存提示，所有行仍完整校验，更多条目会正常增长。元件成员集合按原生已存类型数预留。63 项行引用/数量缓冲在同次加载中复用，每枚开始前清空所有项，避免旧行/旧数量残留。

完整性检查继续覆盖类型数、每行存在/类型、正数量、旧 Cnt 回退、原版六种数值转换、long 溢出、总计核对和缺失模组整枚隔离；未知整枚 NBT 原样保留。源备份/摘要、UUID、持久化逐键重挂载、原子所有权提交及失败保护未修改。

## 方法与结果判断

环境：macOS aarch64，JDK 17.0.20.1，2 GiB 堆；AE rv3-beta-1082-GTNH / AE2FC 1.5.108-gtnh，真实 ApiStorage。优化前冻结 v1.34.4（4c8370b3cd0b18b472185f9085b57ccadf7333ed）源码，仅改类名；所有臂使用相同元件 NBT/压缩字节。

每负载三个独立 JVM；每项每臂预热 20 次、采样 60 次，顺序轮转。表格为三进程 P50 的中位数。普通 AE 直接执行真实原生解码器，公共臂保留完整校验和上线前位置索引。六轮共 155574 项完整身份、数量及源 NBT 断言。

**本轮收益以减少对象分配为主，加载 CPU 耗时仅小幅改善；不能据此承诺所有机器固定提速或已经完全等同普通 AE。** 微小耗时差异需要结合噪声看待，原始分位数和每轮结果均保留。

## 正确性与兼容性

- build / spotlessCheck 通过，原生存储回归 40957 项，新增 2651 项。覆盖查询结果正/负记忆、预算内重复身份只查一次、下一次加载识别恢复的注册项、大量不同类型超过记忆预算后的正确退化、全部缓冲清零、不可变且独立的最终快照，以及证明原生池快照不走中间条目集。
- 单枚→多枚→耗空首枚提升→恢复单枚→完全耗空→重新入库的物品/流体转换通过；原有近 long 上限、多盘、模拟、限额/托管、原生内部写入及旧句柄失效继续通过。
- 2400 组冻结/新版检查器随机对照继续通过，新版在各个样本之间复用同一个上下文，覆盖失败后及不同行数之间清零；包括 0–63 行、六种数值类型、旧 Cnt、未知模组、错类型、缺行、溢出和额外字段。
- 额外加载每通道 16385 种、合计 32770 种资源，81928 项断言通过，证明预分配提示不是存储上限。该轮仅预热 1 次/采样 3 次用于正确性，不将其分位数当作性能结论。
- 原有 46 项迁移、103306 项产线统计优化及全部 IO 回归通过。保存负载各在独立进程验证完整库存及缓存；客户端/集成服务端验证见 [交付说明](1.34.5-改动与交付说明.md)。
- 存档格式版本 1 不变；1.34.0–1.34.4 原生存档直接加载，更早旧共享数据仍沿用自动迁移。网络协议、产线归属及统计口径没有改变。
