# AE 无线发信端安全归属修复

## 现象与原因

发信端接入带 ME 安全终端的网络后，方块自动碎掉并掉落。原实现仅把放置者 UUID 写入无线控制的队伍归属，没有调用 AE 网络代理的 `setOwner(player)`，导致 AE 节点初始化时的玩家 ID 为 `-1`。

当前锁定的 AE2 `rv3-beta-1082-GTNH` 在建立网络连接时调用 `Platform.securityCheck`。当目标网络有启用的安全终端且无主节点没有建造权限时，节点初始化会安排 `MachineSecurityBreak`；继承自 `AEBaseTile` 的 `securityBreak()` 会调用世界的方块拆除及掉落逻辑。多个发信端的冲突处理仅决定谁响应查询，不执行方块拆除。

## 修复

- 放置时同时设置无线队伍归属和 AE 代理的真实放置者，使 AE 在首次连接邻接节点前取得玩家身份。
- 旧存档的 AE 节点 ID 缺失时，在代理读取节点数据后、调用 `updateState` 建立邻接连接前，根据已保存的所有者 UUID 恢复 AE 玩家 ID，所有者无需在线。
- AE 玩家数据接口要求完整 `GameProfile`，但实际按 UUID 映射 ID；离线恢复以 UUID 文本补全接口要求的名称，不创建假玩家、不发起在线查询。
- 保留有效的已有 AE 玩家 ID、网络安全键和原生权限检查。没有所有者信息的节点不会冒用网络所有者；玩家没有建造权限时仍按 AE 规则拒绝接入。
- 通道、0.5 AE/t 空闲功耗、队伍隔离及改名行为保持原规则。同步只在放置和节点加载时发生，不增加逐 tick 扫描或轮询。

## 验证与兼容

`gradlew.bat --offline verifySupplyTracking` 中加入了 15 项检查，使用真实 AE `PlayerData`、代理 NBT、节点和 `Platform.securityCheck`：覆盖原始无主节点被拒绝及拆除、实际放置者同步、有权限节点接入、NBT 保存与重载、离线修复旧 ID、有效 ID 保留、无建造权限和无所有者的拒绝行为。

交付检查：`gradlew.bat --offline build spotlessCheck`。自动化验证不替代实际服务器里的安全终端接入测试。

没有新增网络协议或 NBT 字段。测试包保持当前版本号；服务端需替换修复包，建议客户端同步同一构建。更新后使用拥有该 ME 网络建造权限的玩家放置发信端，旧节点会在重新加载时修复缺失归属；已经被拆掉的方块需重新放置。
