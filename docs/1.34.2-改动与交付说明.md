# 1.34.2 改动与交付说明

将公共 AE 的资源位置索引改为增量维护，消除正常数量变化、失败取料和兼容直写中的反复全量重建。数量仍由原生 AE2 / AE2FC 元件持有。

## 行为与兼容

- 资源出现或耗空时才改变所属元件；正常数量变化不扫描整盘，失败请求直接返回。使用有结构失效机制的私有身份缓存，跳过没有目标资源的元件。
- 兼容直写优先使用已有位置和未满元件；旧服迁移批量写入后，为实际变化的元件统一建索引。两通道全部成功后才清空旧解码器，失败时保留完整旧数据。
- 保留限额、托管预留和聚合数量上限；修正分配器模拟部分限额时重复报告容量的问题。原生集成解包后直接写入时，通过保存回调修复对应元件的索引。
- 产线和 IO 统计继续按实际成功量记录，模拟、失败及回滚规则保持；UUID、绑定、库存格式和网络包编号不变。
- 已有 1.34.0 / 1.34.1 原生存档只重建内存索引；更早旧共享池继续沿用原始备份、SHA-256、重挂载核对和原子提交。无需重新绑定设备。

## 实测性能

4096 种物品 + 4096 种流体、同种原生元件、3 个独立 JVM。单位 µs，表中为三个进程 P50 的中位数；混合搬运是物品、流体各取出并放回，共 4 次实际存取。

| 操作 | 1.34.1 公共 AE | 1.34.2 公共 AE | 普通 AE |
| --- | ---: | ---: | ---: |
| 无 NBT 混合搬运 | 790.21 | 47.38 | 60.38 |
| NBT 混合搬运 | 1806.83 | 80.63 | 74.00 |
| 无 NBT 空库存取物品 | 539.96 | 1.08 | 2.33 |
| NBT 空库存取物品 | 1461.04 | 4.13 | 6.67 |

同规模首次迁移三次观察：无 NBT 约 89–93 ms，NBT 约 152–158 ms。主要搬运、缓存查询、枚举和保存已接近原生路径；加载仍有完整性检查与兼容索引的额外成本，不能承诺各方面耗时相等。这些是隔离存储引擎测量，不是生产服 TPS。

[完整性能报告及原始数据](https://github.com/fyt7943tyf/futa_gtnh/blob/main/docs/1.34.2-原生存储索引优化性能对比.md)同时列出旧共享池、冻结旧公共阵列和普通 AE 的对比、分配量、加载差距及测试边界。
