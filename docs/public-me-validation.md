## 实际客户端与世界检查

```sh
./gradlew runClient17 -PuiSmoke --console=plain --offline
```

该脚本仅允许修改目录名为 `FutaUiSmoke`、世界名为 `Futa UI smoke` 的隔离开发存档。它运行真实客户端和集成服务端，确认：

- 远离出生点的核心区块真正加载，原生控制器和六个端口建立公共网络。
- 旧池的物品和带 NBT 流体在原生 ME 监视器中只出现一次；模拟不写入，实际存取数量守恒。
- 公共接入器 → 原生透明 ME 玻璃线缆 → 原生 ME 驱动器形成真实连接。
- 驱动器里的一张原生 1k 盘持有 23 个带 NBT 的物品；共享背包门面能读取并取出，而内部池始终没有复制这 23 个物品。
- 主世界及下界的上述结构连接同一个公共网，测试结束清理测试设备并释放临时票据。
- 重启后仓库 UUID 和实体核心坐标与上一次正常停服写出的存档相同。

成功标记为 `PUBLIC_ME_SMOKE_SUCCESS` 与 `PUBLIC_ME_RESTART_SUCCESS`。

真实 GL 渲染检查还生成了 16 个页面截图，包括产线管理、AE 合成及不同 GUI 缩放。新增页面的截图使用明确的客户端展示夹具，不是服务器产线实测数据；实际服务端存取由上述独立烟测验证。截图默认位于 `run/build/ui-smoke/screenshots/`，不随源码或模组发布。

## GTSWN 1.8.8 兼容补充（2026-10-27）

迭代版本仍为 `1.33.6`。使用官方发布的 `gtswn-v1.8.8-dev.jar` 加入开发运行时，执行：

```sh
./gradlew runClient17 -PuiSmoke \
  -PgtswnCompatJar=/绝对路径/gtswn-v1.8.8-dev.jar \
  -PrunClientWorkingDirectory=run/gtswn-client --console=plain --offline
```

`gtswnCompatJar` 只向开发运行时添加本地 jar，不会把 GTSWN 打进 Futa 发布包。使用独立运行目录及严格限定的 `FutaGtswnSmoke` 存档（世界名 `Futa GTSWN smoke`），不操作日常开发客户端的存档。

最终客户端与集成服务端检查通过 **203 项**断言，成功标记为 `GTSWN_QUANTUM_SMOKE_SUCCESS`，覆盖：

- 原生 1.8.8 终端普通右键公共接入器，执行 GTSWN 原有量子化、持久化注册和绑定流程；多个终端独立绑定。
- 核心量子化后，六个原生控制器端口连接仍在线；重启后仍能建立公共网络。
- 主世界和下界中，通过原生终端实际放置的量子节点与相邻 ME 驱动器加入同一个公共 AE 网格。
- 量子桥接落在公共端口上；原生盘中的 23 个带 NBT 物品可从共享门面读取、取出，没有复制到旧池；节点监视器流体存取数量与 NBT 守恒。
- 节点 NBT 保存和实际原生节点的 NBT 读回保留端口选择；终端解绑保留外部 NBT、公共量子化状态、其他终端及已有节点。
- 普通私人控制器保留原生连接面过滤、绑定及取消量子化行为。
- 同一分支使用真实致密线缆连接 33 台 ME 驱动器，稳定后只有 32 台获得频道，公共端口实际用量为 32。
- 已接入分支随后接上独立控制器时被隔离；公共网络恢复；移除独立控制器后该量子分支自动重连。

`PUBLIC_ME_RESTART_SUCCESS`、原有公共 ME 世界烟测和 16 个 GL 界面检查也通过。`spotlessApply build spotlessCheck` 在未安装 GTSWN 的默认依赖下通过；供应追踪验证配置包含三个可选兼容 Mixin，用于检查缺少 GTSWN 时能跳过这些目标。

以上验证使用固定版本 AE 1082 和 GTSWN 1.8.8；兼容 Mixin 在读取 GTSWN 版本常量后仅对 1.8.8 启用，不将结果推广到其他 GTSWN 版本。尚未验证完整生产服全部第三方模组组合或长期负载。

## 尚未替代的验收

这不是对生产服全量旧存档、长时间运行、所有第三方机器和实际复杂合成产线的验收。原生合成计划器与 CPU 提交接口已接入，但截图中的合成计划是展示夹具，不代表一次真实复杂合成任务的完成证明。升级生产服前使用完整世界副本核对库存、机器区块、既有 CPU 任务和产线；迁移与恢复边界见 [迁移说明](public-me-migration.md)。
