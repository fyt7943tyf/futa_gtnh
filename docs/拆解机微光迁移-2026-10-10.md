# 拆解机迁移 GTNL 微光规则

## 来源与目标

按用户要求弃用旧配方判断，迁移 `ABKQPO/GT-Not-Leisure` 的微光配方转换方式。固定 `dev-290` 提交 `c9614667efbbcbc5b9eed89c76807caeea4b1e5e`，参考 `DisassemblerHelper`、`ReversedRecipeRegistry`、`ShimmerRecipes` 与两种 GT 配方构造器 Mixin。机器仍为低价 LV 单方块，32 EU/t、1A、40 ticks，每次一个生产步骤。

旧的 `DisassemblyCrafting` 和 `DisassemblyIngredients` 已删除，不再保留第二套严格筛选或虚拟合成校验。

## 行为核对

| 项目 | 迁移后的行为 |
| --- | --- |
| 工作台来源 | GT 有序/无序构造器原始参数，仅 GT `ItemMachines` 成品；不另扫原版/Forge/NHCore Universal 工作台 |
| 配方移除 | 构造时记录的 GT 路线仍在记录中，遵循微光，而非最终工作台列表 |
| 3×3 形状 | 直接 `GTUtility.reverseShapedRecipe`，不再模拟网格 `matches`/合成结果校验 |
| NBT/附魔标志 | 保留成品静态 NBT，忽略 GT 工作台保留 NBT/附魔标志，不构成整项禁用 |
| 工具 | 构造器过滤 `craftingTool*` 字符串，GT 反转函数过滤 GT 工具；未广泛添加工具种类限制 |
| 矿辞 | GT 标准优先，缺少标准时使用 GT 函数的矿辞候选回退；缺失候选由该函数单独忽略 |
| 通配符 | 自动转换中非耐久物品归零，耐久物品保留通配值；输入按 GT 通配符匹配 |
| 容器 | 自动转换单独去掉容器项，保留剩余材料；原样返还分支不增加容器过滤 |
| 组装机路线 | 按 GTItemStack 分组，首条路线；其他路线的相同槽位/前缀用于微光廉价替换 |
| 材料替换 | 完整照搬廉价材料、Any、磁性/退火铜、木材/圆石/钻石、陷阱箱及电路表；陷阱箱固定返还 1 箱的上游行为也保留 |
| 电路 | NHCore ULV～MAX 指定最便宜电路；明确按材料常量判断，不能用材料 `name()` 推导等级，因为 LV 等是别名 |
| 实机接口 | 实机 NHCore 2.9.71 是 `get(int)`，可选物品桥同时支持 int/long 及 varargs，不强制新增 NHCore/TecTech 依赖 |
| 自动输入过滤 | GT 工具、电路、矿石/碎矿、解包机及完整微光黑名单；只用于自动组装机和 GT 工作台 |
| 旧的特殊限制 | 不额外禁用状态材料、自定义/禁用/假组装机配方、概率输入输出、副流体输出和备选流体 |
| 多输出 | 自动组装机要求单成品；可视装配线/太空组装机/硬覆盖采用首成品，与微光分支一致 |
| 原样返还 | 可视装配线、太空组装机和硬覆盖不套用自动材料转换/输入黑名单 |
| 优先级 | 已安装 GTNL 的转换与硬覆盖 → 组装机 → 可视装配线 → 太空组装机 → GT 工作台 |
| 去重及匹配 | 去重忽略 NBT 并考虑数量；执行按 GT 元数据通配符及严格 NBT 匹配，空 NBT 与无 NBT 不被主动合并 |
| 坏路线 | 只记录本条失败，不移除已经有效的成品转换；不存在全产品冲突 veto |

材料转换先复制正向配方物品，避免微光原函数部分路径会直接修改源 ItemStack 的副作用；数量和返回规则保留。GTNL 调试索引及世界流体交互没有迁到机器。

## 机器适配

- 保留原批次，不作 GCD 缩减。例如生产 4 件用 8 个零件和 144 mB，拆解也以 4 件为一批，返还 8 个零件和 144 mB。
- 世界微光即时处理输入中的所有完整批次；机器每 40 个付费 tick 处理一批，剩余留在输入栏。此为执行载体的区别，材料转换规则一致。
- 超过合法堆叠的批次按多次输入收集，内部保护槽保存原成品，凑齐前不耗电。GUI 用两个整数同步待齐备数量，不同步超大 ItemStack；NBT 加 `fullCount`/`batchCount` 保存整数数量，并兼容没有新字段的旧任务。
- 拆机前拆分保护槽为合法物品堆，GT 掉落全部库存；不会把任务计划和原输入重复存到机器物品。
- 最少 36 个物品槽、8 个 64,000 mB 罐，按最大批次扩大；旧机器和目录尚未加载时创建的机器原位扩容，不清库存、进度或液体。
- 原料流体以及导入的 GTNL `ItemFluidPacket` 返还为真实流体，保留数量与 NBT。输出满则等待，最终一次结算。
- 安装 GTNL 时跟随其首次 tick 调度，在 LOWEST 阶段导入已加载的微光转换表及尚未清空的硬覆盖表；不修改 GTNL 数据。未装 GTNL 时独立用迁移算法生成，不额外添加 GTNL 的生产配方和专属物品。
- 太空组装机通过可选 Intergalactic 配方表读取。网页索引等待拆解目录就绪，内部缓存版本 14 → 15；NEI 类别顺序保留 10000，用单件物品查询也能展示多件输入批次。
