# 1.34.7 改动与交付说明

沿用 1.34.6 的 `publicME.storagePriority` 配置和原生优先级修复。

共享 IO 的主动搬运和旧 Futa 存储总线改为托管真实 AE/AE2FC 部件。保留原方块、物品与 TileEntity 注册标识、坐标、六面配置、界面和产线身份；升级不要求拆除或重摆设备。

| 旧功能 | 实际执行部件 |
| --- | --- |
| 物品抽入 / 输出 | AE `PartImportBus` / `PartExportBus` |
| 流体抽入 / 输出 | AE2FC `PartFluidImportBus` / `PartFluidExportBus` |
| 旧存储总线的物品 / 流体通道 | AE `PartStorageBus` / AE2FC `PartFluidStorageBus` |

六面可分别启用物品和流体的抽入、输出、双向。一个旧方块内部可托管多个部件；同面双向仍先抽入后输出。原生部件的节点直接加入公共 ME，由 AE 的 TickManager 调度，实际容器访问、适配器选择、搬运和库存通知沿用原生实现。兼容部件不占用旧公共线缆端口的频道额度，普通玩家放置的 AE 设备仍按原规则计算频道。

保留原有间隔、数量档位、空闲退避与手动物品按配置间隔重试。物品白名单仍先于矿辞规则尝试，显式排除优先；超过原生九格的旧列表完整保留，转换为原生输出部件的派生配置，不截断。纯配置不是库存副本；实际数量始终由 ME 读取。旧存储总线保留优先级、读写/只读/只写、空名单、黑名单、精确/忽略 NBT/矿辞匹配语义。读取模式可看见原有容器内容，抽取仍尊重原生适配器与机器的权限；只写内容继续隐藏。

旧共享终端的被动 `ISidedInventory` / `IFluidHandler` 保留整网视图与原有面配置，继续委托 ME，避免变成九槽接口缓冲而改变管道使用方式。共享库存仍使用现有 AE/AE2FC 原生元件，没有新增一套可花用的共享数量池。

原 IO 的来源 ID（类型、维度、坐标、面）不变，真实原生操作回映射到原 IO，保留产线绑定和“历史随 IO 改绑”的现行规则。两个旧总线挂载同一目标时只发布一次对应资源的可读数量；采用原生适配器查询，并在重复监控回调时要求原生网络重新枚举，避免把变化量重复相加。只保留枚举策略，没有另做容器读写器。

存储总线统计改为包装 AE 自己创建的处理器，兼容旧 AE2 的双参数构造和新 AE2 的三参数构造；原生构造、筛选及跨网枚举逻辑继续保留。

原来的 `TerminalIoEngine` 和 `LegacyMeBusProvider` 已移到 `tools/`，仅供旧行为、冻结适配和守恒回归使用，不进入正式 JAR，也不在生产路径运行。旧登记表的清理入口仍兼容残留链接；正常设备由原生节点发布和退出。

升级保护：

- 按已加载区块懒初始化，不强行加载整张地图或相邻区块，不为了转换执行器移动机器中的物品、流体。
- 保留原始旧 Tile NBT、当前原生部件状态和暂停原因。检查点使用版本 1 与规范化 SHA-256；未知版本或校验失败时保留原始 NBT、暂停接入，不以空配置覆盖。
- 新物流启用前，将服务元数据写成版本 4 并读取磁盘确认。旧 1.34.5 读者会拒绝该服务版本，防止重新启动旧搬运器。原生元件存档格式仍为版本 1；已有 v2/v3 元数据及更早共享文件仍可读取、迁移，原有旧库存迁移备份、来源校验、所有权标记和逐资源检查保留。
- 正常主动传输由原生部件完成；原生回调外加持久托管保护。AE2FC 的先注入后抽取路径改为容量预留，实际抽取后才提交确实取得的流体。部分接收、短抽取、拒绝回退均按实际数量结算；已确认但退不回的余量进入原生回收路径。
- 源回调、目标回调或原生存储总线回调的结果不明时，保留未决托管并暂停对应设备，重启后不自动重放，也不恢复旧引擎。出现异常资源返回时保留实际返回资源，避免按模拟资源退款。
- 终端的真实输入余量新增持久化，数量使用整型字段，拆除时只处理实际余量，不把整网虚拟槽位变成掉落。缺失模组的余量保留原始 NBT，阻止覆盖，并可随恢复载体保留。

网络包格式和原方块注册标识未变；建议客户端、服务端一起更新。启用新物流后的存档不支持直接降级旧执行器。保护针对仍存在的持久化数据；旧版本从未保存且已在此前停服消失的内存数据无法恢复。跨机器区块的硬崩溃落盘不是跨区块事务，异常未决记录需要结合实际机器状态与服务器备份核对，不能盲目重放。

本轮保留旧配置、共享接入、产线身份和异常保护的适配成本；原生部件执行不等于已经证明与普通 AE 在所有场景耗时相同。本轮验收重点是原生执行、配置兼容、库存守恒和升级保护。
