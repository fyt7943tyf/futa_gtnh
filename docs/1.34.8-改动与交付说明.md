# 1.34.8 改动与交付说明

## 修复 AE 无线发信端接入后自动碎掉

发信端接入启用 ME 安全终端的网络时，原实现只保存无线队伍归属，漏向 AE 网络代理设置实际放置者，导致节点以玩家 ID `-1` 接入，被 AE 的安全检查视为未授权设备并拆除。

本次在放置时同步 AE 代理的真实放置者。旧存档节点缺失 AE 身份时，在首次连接邻接网络前按已保存的所有者 UUID 恢复，无需所有者在线；有效的已有 AE 玩家 ID 和网络安全键予以保留。

AE 原生建造权限继续生效：玩家没有该网络的建造权限，或节点没有可恢复的所有者时，仍按原生规则拒绝接入。无线队伍隔离、每网络单个生效发信端、通道和空闲功耗规则保持原样。同步仅在放置和加载时发生，没有增加逐 tick 扫描。

## 验证与兼容

- `gradlew.bat --offline build spotlessCheck`：完整构建、格式及既有回归检查。
- 15 项安全归属检查使用真实 AE 玩家数据、代理 NBT、节点和原生安全检查，覆盖无主设备的拒绝与拆除、实际放置者同步、有权限接入、NBT 保存和重载、离线恢复旧节点、有效 ID 保留和无权限拒绝。
- `python -m unittest discover -s tools/release -p 'test_*.py' -v`：发布流程规则检查。

没有新增网络协议或 NBT 字段。服务端需更新，建议客户端同步同一版本；更新后用有该 ME 网络建造权限的玩家放置发信端，旧节点重新加载时会恢复缺失归属，已经掉落的方块需重新放置。自动化检查不替代实际服务器中的安全网络接入验证。

实现与触发链路详见[AE 无线发信端安全归属修复](AE无线发信端安全归属修复.md)。
