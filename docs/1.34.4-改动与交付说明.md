# 1.34.4 改动与交付说明

继续减少公共原生 AE 加载成本，保留上线前完整解码、计数核对、缺失模组整枚隔离及旧服迁移保护。

- 复用原生元件已解析的内容与规范化身份，省去重复全量列表及标签内部化；私有物品定义独立复制并重新计算哈希，避免调用方修改栈污染索引。
- 原生资源位置索引仍在挂载返回前完整构建；额外 `ItemKey/FluidKey` 索引改为按资源需要缓存，普通 AE 存取不生成无用兼容键。首次全量兼容快照已单独计时，耗空/清空/重挂载同步失效缓存，数量始终来自真实原生元件。
- 完整性检查合并读取资源行与数量，保留全部正数量、缺行、原版数值转换、溢出及总计核对。缺失模组与损坏额外字段并存时保持旧版隔离/拒绝行为，整枚原始 NBT 保留。快速遍历不可用或遇到 NBT 子类时回退公开访问器。
- 同机三个独立 JVM、8192 种资源配对测试：无 NBT 的解压＋挂载从 10.13 ms 降至 8.61 ms（约减少 15.0%），普通 AE 6.45 ms；带 NBT 从 15.53 ms 降至 12.43 ms（约减少 20.0%），普通 AE 9.60 ms。差距缩小，仍未完全持平。
- 带 NBT 的首次全量兼容快照（含已解压挂载与所有兼容键创建）从 15.69 ms 降至 12.72 ms；已解压挂载累计对象分配约减少 56.6%。普通 AE 基线直接强制执行原生解码器，不再为了强制加载额外造一份列表，详见 `docs/1.34.4-原生AE加载与兼容索引性能对比.md` 及六份配对、两份完整路径 JSON。
- 原生存储回归 38306 项（新增 5825 项）通过，包含 2400 组检查器随机对照及访问器回退、私有定义隔离、冷兼容缓存的原生存取/全量枚举、耗空/补回、首次兼容快照与重挂载。原有 46 项迁移和全部产线/IO 回归继续通过。
- `build spotlessCheck`、发布控制器 30 项测试通过。六轮配对基准共 155574 项、两轮完整路径共 434208 项断言通过；两种保存负载各在独立进程通过 24580 项逐键/缓存重挂载检查。
- 真实隔离客户端和集成服务端：旧共享存档自动迁移、已有 1.34.3 原生存档直接重启，UUID、完整 NBT、长数量、限额、未决托管及已消耗数量正确；原始旧文件字节不变。保存、重挂载、重新加载和坏版本保护通过。
- 两套环境均通过公共 ME、跨维度原生盘、手持产线终端、双总线实际 56 件/12000 mB 统计、零库存历史及 26 个 GL 页面。仅使用开发存档，未操作生产服。

存储介质与原生数据格式版本 1 不变，1.34.0–1.34.3 原生数据不重新导入旧池；更早旧共享文件继续自动迁移，备份/来源摘要、持久化逐键核对、原子所有权提交和失败保护不变。网络协议和历史归属规则未改变，建议客户端/服务端一同更新。开发夹具、冻结源码及基准工具不进入正式 JAR。
