# 原料去向追踪

入口为共享终端顶部的“追踪”，提供领料排行、库存趋势和低库存预警。本轮不包含自动停机或最低库存拦截。

## 记录边界和归属

公共 ME 网络通过原生 `NetworkInventoryHandler` 的实际 `MODULATE` 存取结果记录流量，普通监视器和直接访问父网库存的优化路径共用同一统计边界，覆盖自动扩容原生元件和外接普通 ME 盘。普通 `NetworkMonitor` 对已接入原生处理器的请求不再重复记账；其他库存实现保留监视器回退。旧共享元件仅在公共网络未运行时沿用 `AbstractSharedCellInventory` 的记录。`PartStorageBus` 的库存处理器仅保留调用期间的入口位置，不改变原生筛选、优先级或库存列表优化。子网存储总线贴主网 ME 接口时，入口是总线所在的线缆方块及其朝向，相邻接口坐标由方向偏移得到。同一原生库存处理器的嵌套转发只在最外层完成时记一次，AE 整理请求 `ReshuffleActionSource` 不记。

AE/GT 的部分优化请求会跳过存储总线处理器，直接调用父网库存。此时优先使用请求设备的来源，在其所属子网内寻找唯一连接当前公共网络、且与请求资源类型相同的存储总线。每次最多访问 64 个机器类别/总线节点，物品、流体的结果按请求源分别缓存 30 秒，缓存最多 1024 项；网络身份变化或总线库存处理器重建会使缓存失效。不加载区块、不扫描全世界；遇到多入口、预算用尽或脱网时退回请求设备坐标，不猜测产线。缓存只保留网络弱引用和不可变位置。识别公共库存时只核对当前公共监视器返回的处理器身份，不缓存失效的处理器引用。

终端主动 IO 在相邻容器实际接收/交出之后按成功量记录，回滚不计入领用。物品、流体都支持；同一终端的不同工作面分开归属。目标已被共享存储总线及其筛选规则纳入同一仓库时，跳过内部搬家统计，包含目标当前为空的情况。本轮同时修正普通物品容器的部分接收结算：写入后核对实际槽位增加量，未接收部分退回共享库，并尊重容器堆叠上限。

记录的是物资跨入口领用/回库，不能证明机器已经消耗。玩家手动从共享终端取料、GT 管道主动抽终端以及其他直接 API 路径暂未纳入。统计仅在服务端主线程接收事件；不为后台线程读取世界或触发扫描。库存趋势采样真实聚合库存，独立于入口统计覆盖范围。

## 开销和容量

| 工作 | 边界 |
| --- | --- |
| 成功搬运 | 常态复用键、来源和计数环，仅哈希查找与整数累加；不创建逐笔事件或写磁盘 |
| 时间窗口 | 保留 60 个分钟桶，增量维护 1 / 10 / 60 分钟累计；分钟边界会有不足一分钟的取整误差 |
| 历史容量 | 4096 种资源、4096 个入口、16384 个资源与入口组合；达到上限显示缺失提示 |
| 过期清理 | 按分钟过期队列扣减窗口累计，每分钟检查有限集合；长时间空闲直接重置累计，不读取世界或容器 |
| 预警 | 最多 128 项，每秒最多 16 次单条库存查询、最多发送 4 项提醒；满额一轮约 8 秒 |
| 趋势 | 最多 256 项，每项 6 个分钟采样；只采样关注或查看过的原料，闲置 10 分钟清理 |
| 界面查询 | 默认每 5 秒刷新；服务端每玩家每秒最多一次查询，设置请求至少间隔 250 ms |
| 产线查询 | 先通过来源索引筛选，再汇总固定窗口；同条件共享最多 1 秒的快照，分页仅构造当前页 NBT |
| 快照容量 | 最多 64 份、合计 32768 个设备/资源/汇总行，按 LRU 淘汰；改绑和分钟切换失效 |
| 网络 | 一次只回当前原料及最多 8 个入口、8 个关注/记录键；不广播整份历史 |
| 持久化 | 保存入口名称、预警及产线归属；历史、趋势和查询缓存重启清空 |

合成计数器微基准只用于检查常态复用与数量正确，不代表整合包 TPS 测量。实际服务器表现仍应结合 Spark profile 验证。

产线历史仍按 IO 记录，查询时使用当前绑定。改绑后保留窗口内的历史一起移到新产线，不按发生时的产线固化归属。固定窗口使用可逆的宽累计，输出时才限制到 `Long.MAX_VALUE`，避免已饱和的累计在过期扣减后产生错误。底层分钟桶仍按原先的 `long` 饱和规则计数；查询优化不改库存、统计入口或磁盘格式。实现和满额实测见 [1.34.1 性能报告](1.34.1-产线查询性能对比.md)。

## 配置、保存与兼容

`enableSupplyTracking` 默认开启，关闭后跳过统计和预警轮询。预警为共享设置，向已支持该功能的在线客户端发送，库存恢复到阈值加约 10% 才重新武装，冷却 5 分钟。名称最多 96 个 UTF-8 字节；预警键限制为可压缩到 2048 字节且 NBT 文本不超过 4096 字符，防止特殊物品放大页面与配置。

配置保存到 `<存档>/data/futa_gtnh_supply_watch.dat`，带临时文件替换和 `.bak`。读取失败或遇到未知配置版本时停止写入并禁用设置编辑，保留原文件，查看服务端日志处理。历史达到容量后不影响仓库存取。

新增协议编号 43（查询/设置）和 44（页面/预警）。客户端先借现有 `PacketStorageAction` 的新动作 36 申明支持，服务器确认后才发送新请求；服务器只向已确认的同一连接推送预警。旧客户端不会收到未知编号，新客户端连接旧服务器时保持等待提示。要使用功能需两端同时更新，现有终端容器与存储持久化格式不变。

“关注”和“记录”每页 8 项，本地搜索仅筛选当前页；普通物品/流体页沿用本地库存缓存搜索。记录页可选择已经耗空的条目。排行使用非负的“取出减回库”，悬停分别展示原始取出和回库量。

## 设备导航

选中入口后可点击“世界高亮”或“传送附近”。高亮只在客户端保留一个位置，不持有世界或设备引用；绘制一个设备边框、朝向标记、指引线和坐标标签。它独立于寻物魔杖，不要求持有道具。跨维度时只在记录维度显示，同维度超过 256 格跳过绘制；5 分钟过期、手动取消或断线时清空。

传送扩展既有 43 号包的动作 3，包体格式和编号不变，不接受客户端坐标。服务器要求当前共享终端窗口、已确认的连接，以及该原料最近一小时内实际记录过的来源。未知来源、玩家来源和非法位置不能传送；配置 `enableSupplyTeleport` 默认开启，每玩家该动作限流 5 秒，与查询和设置分开。

只查询已加载的目标维度与区块，要求记录位置仍有设备。每次点击最多在 17×13×17 范围寻找现成落点，检查站立面、身体碰撞、附近液体和火；失败时保留界面且不移动玩家，任何路径均不挖方块或创建传送门。跨维使用 Forge 的维度迁移和直接落点 Teleporter，保持目标绝对坐标，不采用下界比例换算；成功后清除动量与摔落距离，关闭终端并在客户端高亮记录目标。设备后来被替换或记录来源本身属于 AE 请求设备回退时，高亮仍指向记录位置。

旧服务器会拒绝未知动作，页面没有 `teleportEnabled` 时禁用传送，客户端高亮仍可使用。旧客户端不会发起传送，也不会收到新的传送回执，因此可以继续使用原有统计功能；要使用新增传送需两端更新。

- `verifySupplyTracking` 新增记录归属授权、过期/非法来源、服务器开关、未加载区块/维度、设备移除、液体/碰撞拒绝、安全落点、失败保留界面、成功清除摔落动量、直接维度落点及不修改方块的检查。
- `verifySupplyGui` 新增高亮切换/自动过期/断线清理、传送回执连接隔离、旧服务器禁用传送、未知来源按钮禁用与新增按钮布局检查。

## 统计验证

- `gradlew.bat verifySupplyTracking`：使用真实 AE Mixin 和共享元件，检查模拟与真实存取、嵌套转发去重、直接父网访问归属、归属缓存及网络切换、IO 部分接收/拒收/回滚/内部搬家、时间桶/容量/过期、阈值/趋势/轮询预算、元数据保存与坏文件保护、协议往返及连接身份隔离。
- `gradlew.bat verifySupplyGui`：调用实际界面初始化、点击和编辑路径，检查 320×240 / 854×480 布局、零库存记录选择、分页、命名弹窗及非法阈值、新旧连接响应隔离。使用测试输入夹具，不启动图形客户端。
- 交付前运行完整 `gradlew.bat build` 和 `gradlew.bat spotlessCheck`。真实整合包内需复核：共享元件主网→ME 接口→子网存储总线→产线取料，及终端 IO→GT 机器的数量、入口位置和恢复补货后的预警。
