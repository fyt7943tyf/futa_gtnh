# 1.34.1 改动与交付说明

优化产线流速查询，避免每次翻页都扫描全部资源与来源的 60 个分钟桶。库存继续由原生 AE2 / AE2FC 元件承载。

## 查询改造

- 增量维护 1 / 10 / 60 分钟累计，按分钟过期队列扣减；使用可逆的宽累计，保留原有桶饱和规则，超大数值过期后仍能恢复准确结果。
- 新增来源到资源组合的反向索引，先筛选产线或单个 IO，再读取相关组合的累计。两个索引共用分钟桶，不复制记录。
- 相同条件共享最多 1 秒的统计快照，翻页只生成当前页 NBT。数量、观察时长和速率使用一致的采样时间；分钟切换、改绑、清空及记录结构变化会使缓存失效。缓存限制为最多 64 份、32768 行。
- 绑定窗口独立查询产线元数据，并缓存有效成员和设备数量；重复检查未变化的接口/存储总线关系不会清掉查询缓存。

历史按现有规则随 IO 当前归属汇总：从 A 改绑到 B 后，该 IO 保留窗口内的历史一起转到 B；自动关联总线同样处理。没有复制或清空记录。

## 满额性能对比

同一 JVM 中对比冻结的 1.34.0 实现与新实现，16384 个组合、4096 种资源、4096 个来源，填满 60 个分钟桶。以下为 400 次查询的中位耗时：

| 查询 | 1.34.0 | 1.34.1 |
| --- | ---: | ---: |
| 全部设备，重建统计快照 | 6.51 ms | 5.29 ms |
| 单产线，重建统计快照 | 5.47 ms | 0.14 ms |
| 单 IO，重建统计快照 | 6.44 ms | 0.38 ms |
| 全部设备翻页，命中快照 | 6.79 ms | 0.25 ms |
| 手持终端绑定窗口 | 6.45 ms | 0.00075 ms |

首次全量查询仍需汇总所有组合。记录热点从约 28 ns/笔增加到 39 ns/笔；满额分钟边界清理单次测量从 6.89 ms 增加到 14.46 ms。这些是进程内合成测试，不代表生产服 TPS。完整方法、P95、分配量和限制见 [性能报告](1.34.1-产线查询性能对比.md)。

## 兼容与验证

- 库存、产线保存格式、UUID、绑定规则和网络包编号保持不变；无需迁移库存或重绑设备。已有客户端继续读取原字段，建议两端同时更新以保持版本一致。
- 历史仍只在内存保留一小时，服务端重启后重新累计；已有容量上限及缺失提示保持生效。
- 103306 项查询优化对拍断言通过，覆盖原实现的计数、分页顺序、物品/流体 NBT、三种窗口、饱和恢复、时间跳跃、索引清理、改绑、自动继承、快照时效及容量限制。
- 完整 `spotlessApply build spotlessCheck`、发版规则 30 项测试通过。测试源和冻结基线不打入发布 JAR。
- 隔离存档的真实客户端与集成服务端通过公共 ME、跨维度访问、手持终端绑定、二合一接口双总线实际流量、原生媒体迁移/保存重挂载检查，以及 26 个 GL 页面；未操作生产服务器。
