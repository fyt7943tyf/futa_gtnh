# 1.29.3：AE 合成投递数量守恒修复

1.29.2 在共享库存发生变更时，直接构造物品/流体栈注入 AE 网络，却没有从共享库扣除实物，可能复制库存；旧的绝对数量基准还会漏掉取空后补入的较小批次。1.29.3 改为预留实物、只投递合成缓存、退回明确的剩余量。

## 行为

- 共享库 64、CPU 需要 16 个中间产物：共享库剩 48、CPU 得到 16。
- 共享库 64、普通终端任务等待 64 个最终产物：CPU 确认完成后返回产物，共享库最终仍为 64。
- 取空后重新入库 16：按实际库存交货，不再与历史最高库存比较。
- 退回预留库存不受自动化上限阻挡；预留期间保留 long 数量的回退容量，外部线程不能占走这部分空间。
- 支持物品、流体及 NBT 身份隔离。合成回调期间不持有共享库存锁；嵌套监听抑制和变更队列交接避免重复投递、遗漏外部变化。
- 失败不会中止服务器 tick。CPU 回调已经开始而结果不确定时，不猜测收货量，不自动全额退款；将预留数量留在托管区，暂停这个条目的自动投递。

## 配置与异常恢复

`ae2CellFeedCraftingCpu` 保持默认 `true`。升级后可继续使用此功能；管理员以前手动关闭过该项时，需自行恢复为 true 才会投递。

OP 用 `/futashared escrow` 查看未决物品和流体。它们不计入可用库存，随共享存档保存，重启不会自动退回。请先关闭投递功能，检查异常堆栈以及接收 CPU/机器；仅确认整批未被接收时才执行 `/futashared escrow refund confirm`。命令要求 OP、明确确认且投递功能已关闭。若部分已被接收，必须按接收记录人工核对托管数量，不能整批退款。

正常共享库存继续写 v2 格式、无需迁移。有未决托管记录时写 v3，旧版本会拒绝读取；问题未处理前请勿降级。缺少对应模组的托管条目会原样保留，不自动变为可用库存。网络协议和客户端 GUI 通道未改。

## 验证

新增 `verifyAeCraftingDelivery`，使用真实生产投递代码、共享存储和 Minecraft NBT，AE 接收侧用接口契约 fixture；覆盖全收、部分收、最终产物全量返回、拒收、多个接收网络、耗尽后补货、long 数量、并发入库、回调异常、非法余量、托管保存/恢复、重复退款、失效凭据、嵌套监听抑制和并发变更队列。

发布前执行 `gradlew build spotlessCheck`；该检查包含新回归以及现有共享存储、AE 对接站、终端、拆解机和探矿仪检查。未在生产服替换 JAR 或运行真实合成任务。此修复不改 AE2-Web/Neo ECO AE 的 Mixin 冲突处理。
