# 1.33.5 改动与交付说明

## 原料去向追踪

共享终端新增“追踪”入口，用于排查多条产线持续取料导致基础原料耗空的问题。支持最近 10 分钟 / 1 小时的入口排行、已耗空原料的历史选择、入口命名及坐标复制、低库存预警和实际库存净变化趋势。

AE 主网通过共享存储元件访问共享库、子网存储总线贴主网 ME 接口取料时，尽量归属到子网总线的位置与朝向。无法唯一识别入口时显示请求设备，不推测产线。共享终端主动 IO 按邻接容器实际接收/交出的数量记录，排除模拟、回滚和共享库内部搬家。

排行反映跨入口领用与回库，物资可能仍在机器缓存中。玩家手动从共享终端取料、GT 管道主动抽终端及其他直接 API 路径暂未纳入；这些路径的变化仍会反映在真实库存趋势中。本轮不提供自动停机或最低库存保护。

## 开销与保存

搬运事件只累加有容量上限的分钟计数，不保存逐笔日志。入口识别带访问上限和缓存，不加载区块或扫描全世界。预警最多关注 128 项，每秒最多查询 16 项库存；界面默认每 5 秒按页请求数据，关闭时不推送历史。

历史保留最近一小时，重启后重新积累；入口名称和阈值保存在存档的 `data/futa_gtnh_supply_watch.dat`，带备份及坏文件写入保护。`enableSupplyTracking` 默认开启，可在服务端关闭。更详细的统计边界和容量见[原料去向追踪](原料去向追踪.md)。

## IO 与界面修复

修正普通物品容器部分接收时按请求量全部结算的问题：尊重容器堆叠上限，写入后读取实际增加量，未接收部分退回共享库存。打开追踪页面时保留当前终端合成栏与光标状态；页面不暂停单机服务端。紧凑按钮布局保留原搜索区域。

## 客户端与服务端兼容性

新增追踪请求和响应协议，客户端先通过既有动作包声明能力并收到确认，再发送新请求。服务器只向已确认的同一连接推送预警，避免给旧客户端发送未知包。现有终端容器、共享物品/流体和库存上限的保存格式不变；使用新功能需要两端同时更新。
