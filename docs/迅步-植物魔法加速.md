# 迅步的植物魔法加速

实现基于 GTNH Botania `1.13.36-GTNH` 源码核对，随 1.30.3 发布。

## 如何使用

手持迅步右键打开设置，在生长页开启独立的「植魔」开关，随后戴进饰品栏。默认关闭，旧物品不会自动开启。与作物、动物共用 1–16 格半径和 1–1000 强度。

强度每 100 个世界 tick 提供相同数量的额外更新，均匀分摊执行：

| 强度 | 额外更新频率 | 理论总速度 |
| --- | --- | --- |
| 1 | 每 100 tick 增加 1 次 | 约 1.01 倍 |
| 100 | 每 tick 增加 1 次 | 约 2 倍 |
| 1000 | 每 tick 增加 10 次 | 约 11 倍 |

这里的速度针对原本每 tick 更新的植魔对象；作物原有的「生长刻数」设置含义保持原样。实际速度还受供能、配方操作、范围与更新预算限制。

## 各过程实际由什么驱动

| 过程 | 原机制 | 加速入口 |
| --- | --- | --- |
| 白雏菊转换 | `TileSpecialFlower.updateEntity()` 调用 `SubTilePureDaisy.onUpdate()`，轮流推进八个邻格的计数，总等待约 1200 tick | 补充花朵自身更新 |
| 产能花、功能花 | 花朵方块实体调用各自 `SubTile` 更新 | 补充花朵自身更新；燃料、mana 消耗及花朵寿命同步推进 |
| 魔力池与石板等物品充放能 | `TilePool.updateEntity()` 扫描池中 `IManaItem`，按传输率从真实来源转移 mana | 补充魔力池更新 |
| 魔力池灌注、炼金等转换 | `BlockPool.onEntityCollidedWithBlock()` 调用 `TilePool.collideEntityItem()` | 每次额外池更新后，对池中的掉落物调用原方块碰撞逻辑 |
| 火花传输、扩散充能 | `EntitySpark.onUpdate()` | 补充火花实体更新 |
| 魔力发射与飞行 | 发射器方块实体及 `EntityManaBurst.onUpdate()` | 分别补充发射器和真实魔力脉冲更新 |
| 符文祭坛、酿造台、附魔台、泰拉凝聚板 | 对应方块实体的工作更新；一些阶段主要等待 mana 到达 | 补充自身更新和范围内供能实体的更新 |

不是修改现实时间，也不是把世界时间向前调。普通随机方块更新不能覆盖这些机制，因此植魔接入与 CropsNH 的专门生长调用分开处理。

## 执行边界

- 仅服务端、仅佩戴并开启时运行。通过明确类型名单识别 Botania；没有安装 Botania 时可正常运行，不添加生产依赖。
- 只对范围内已加载的有效对象补 tick。目标已移除、失效、死亡或移出范围时立即停止。
- 保持原配方、催化剂、mana 扣除、材料扣除、容量和手动触发条件。祭坛需要的活石/森林法杖操作不会自动代办。
- 魔力池产物的防连续转化保护年龄不被跳过；不额外更新普通掉落物，不加速其自然消失或拾取时间。
- 多位玩家在同一世界 tick 命中同一对象时只应用较高的额外刻数，不按人数叠乘。
- 每个世界每 tick 最多补充 4096 次对象更新，方块遍历位置轮转。预算不足时实际加速降低。
- 只加速范围内的供能链；不足的燃料和 mana 不会凭空补齐。依赖昼夜、全局世界时间或玩家物品自身更新的过程不会自动变快；未列出的 Botanic Horizons 或其他附属方块也不作覆盖承诺。
- 开关随迅步 NBT 保存。配置包尾部新增可选字段；旧配置包缺少该字段时保持植魔开关不变。要操作新开关，客户端与服务端需一起更新至 1.30.3。

## 验证

专项检查 `verifyBotaniaAura` 使用真实 Botania 类和内存世界，通过 144 项检查，包含实际白雏菊转换、魔力石板充能、魔力池碰撞转化及火花传输的资源守恒，以及范围、客户端禁用、旧物品默认关闭、NBT/配置包、多人重叠、移除目标和大范围预算。

测试专用 Botania dev 依赖不进入生产包。独立测试使用 Java 8 运行原版 Forge 的枚举注册；游戏仍沿用项目原有的现代 Java/lwjgl3ify 启动环境。

未进行游戏内客户端/服务端联调，需在实际花田和供能链中确认操作手感与性能。
