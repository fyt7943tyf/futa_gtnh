# 时装盔甲显隐的 UUID 兼容

Cosmetic Armor Reworked 1.0.7-GTNH 按 UUID 保存客户端时装缓存。正版启动器连接离线服务器时，本地玩家的 UUID 可能与服务器分配的 UUID 不同：服务器已保存的隐藏设置同步到一份缓存，自身界面和渲染却读取另一份默认缓存，表现为重登后显隐重置。

FutaGTNH 在两端更新后自动兼容，无需配置：

- 服务端在玩家登录时通过新的 S2C 包号 37 发送该玩家实际的 UUID；只在安装时装模组时发送。
- 客户端 Mixin 将时装模组查询自身缓存时使用的 UUID 统一到服务端 UUID，直接复用时装模组已有的缓存对象。原生同步包先到或后到都能生效，时装物品及其 NBT 同样使用该缓存。
- 其他玩家的查询保持原样。映射绑定到具体连接，连接建立时重置、断线时清理，旧连接迟到的身份包和断线事件不能污染新连接。
- 没安装时装模组时跳过 Mixin。连接未提供身份同步的旧版服务端时保持时装模组原行为。

本兼容不修改玩家实体 UUID，不修改 `online-mode`，不迁移、删除或重写玩家文件，也不更改时装模组 jar。客户端与服务端应同时更新 FutaGTNH；只有服务端更新无法修复旧客户端的缓存查询。

## 验证

`gradlew build spotlessCheck` 包含 `verifyCosmeticArmor` 与 `verifyCosmeticArmorOptional`。

回归通过 LaunchWrapper 实际应用生产 Mixin，使用官方时装模组类、原生时装同步包及 NBT 编解码，检查：

- 四个槽位显隐、空时装槽、带损伤值和自定义 NBT 的时装物品；
- 身份包与原生同步包的两种先后顺序、本地修改及后续原生同步；
- 其他玩家数据隔离、重登、换服、旧连接迟到事件；
- 正版 UUID、任意服务端 UUID，以及启动器没有 profile UUID 的离线身份；
- 时装模组缺席时的可选依赖守卫及公共服务端代码链接。

游戏内验证步骤：两端更新并重启后，将四个部位设为不同显隐状态，退出重进确认保留；放入时装物品后再重登；由另一名玩家观察外观，并确认其自身设置独立。自动检查不替代真实多人游戏的完整渲染验证。
