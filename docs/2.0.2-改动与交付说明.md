# 2.0.2 改动与交付说明

## 修复 2.0.1 与 ProgrammableHatches 同装时启动崩溃

2.0.1 新增的 GT 存储输入总线保护重定向了 `MTEHatchInputBusME.endRecipeProcessing` 里的 `Platform.poweredExtraction` 调用。ProgrammableHatches（0.2.1p7）的 `MixinMEBusOverride` 也要重定向同一个调用点，而 Mixin 一个调用点只允许一个重定向，后应用的那个报 `0/1 succeeded`，`MTEHatchInputBusME` 加载失败，整合包在 preInit 阶段崩溃。**2.0.1 不要和 ProgrammableHatches 一起使用，请直接升级到 2.0.2。**

本次改动：

- 不再重定向 `poweredExtraction`。改为重定向 `getItemInventory()`，返回一个只记录"真实抽取（MODULATE）取走了什么"的网络视图；其余调用原样转发。抽取不足时，退回的仍然是这次实际从网络里取走的物品。
- 所有钩子改为 `require = 0`，并把 Mixin 优先级调高。以后即使别的模组占了同一位置，本模组的保护自动停用，而不是让游戏起不来。
- 被 ProgrammableHatches 等通过 `IMEHatchOverrided` 改了抽取来源的总线，整个保护跳过：这类总线的物品不一定来自 AE 网络，限量和退回都不适用。
- 日志改为"计划抽取 / 实际抽到 / 能为计划量付出的能量"三个数字，其余保护逻辑与 2.0.1 相同（按能量限量模拟抽取、仅在 `checkRecipe()` 内退回、`-Dfutagtnh.stockingBusGuard=false` 可关闭）。

## 验证与兼容

- `gradlew.bat --offline build spotlessCheck`：完整构建、格式及既有回归检查。
- `verifyStockingBusGuard` 20 项检查：真实 Mixin 变换 GT 的总线和多方块基类，用假 AE 网络驱动。新增两项：一个与 ProgrammableHatches 同形的**必需重定向**（`require = 1`）和本模组的 Mixin 同时应用并仍然执行；能量只够抽 25 件时，这 25 件退回网络。
- 已用整合包 daily 823 的 GT5U 5.09.55.2 核对 `getItemInventory()`、`endRecipeProcessing`、`updateInformationSlot`、`checkRecipe()` 的签名一致。
- 在带 ProgrammableHatches 的整合包实例上本地启动验证通过。

没有新增网络协议、NBT 字段或配置项，仅服务端生效。
