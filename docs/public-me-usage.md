# 公共 ME 网络、产线统计与自动合成

这一版将共享背包的读写接到真实 AE 网络。默认的共享范围仍是全服公共仓库；B 键、共享终端、旧 IO 和旧存储总线继续提供入口，原生 AE 设备可以接入同一个公共网络。

旧库存采用原地接管，具体备份、迁移标记与恢复边界见 [公共 ME 迁移说明](public-me-migration.md)。请先在完整世界副本中验收升级。已在隔离的开发存档中完成真实客户端和集成服务端检查，结果见 [验证记录](public-me-validation.md)；这些检查不包含你的生产服存档。

## 安装与版本

客户端和服务端都需要替换为同一份新构建的 jar；新增的产线和合成页面、请求协议需要两端一起更新。这次迭代保持 `version.txt` 不变，所以产物名称会与现有版本相同，需要覆盖原 jar，而不是同时放入两个版本。

本实现针对项目当前固定的 GTNH AE2 依赖。自动合成使用原生 AE 的样板、计划器与合成 CPU，流体也通过该版本的 AE 流体通道处理。

## 把设备接入公共网络

1. 放置「公共 ME 接入器」，在任一面连接普通 ME 线缆或致密线缆。
2. 在线缆这一侧接原生 AE 终端、接口、输入/输出总线、存储设备或合成 CPU。
3. 右键接入器查看状态、当前端口、本链路频道数和该端口总频道数。
4. 潜行右键在公共核心的六个端口之间切换。切换会重新建立连接，等待 AE 寻路完成后再检查状态。

接入器能位于不同维度，它们连接同一个公共核心。每个核心端口具有 **32 个真实 AE 频道**，六个端口共提供最多 192 个端口频道；多个接入器选择同一端口时，共用该端口的 32 个频道。连接数量、普通线缆的 8 频道限制、致密线缆容量和 AE 寻路规则仍然生效。增加一个接入器不会凭空增加该端口的频道容量。

一个已经含有独立 ME 控制器的网络不能直接与公共控制器合并：接入器发现其他控制器时会保持隔离并报告原因。要让原有独立网络继续独立运行，应使用原生 AE 的接口/存储总线边界进行存储联动，并按各自网络配置终端与合成 CPU。存储联动不等于共享合成 CPU 或合并网络。

公共核心只为自身所在的 **一个区块**申请常加载。接入器、外部箱子、生产机器、样板接口和合成 CPU 的区块仍需要按服务器原有规则保持加载。跨维度连接和 B 键远程访问不会自动加载这些设备所在的区块。目标区块卸载时，相应设备、库存和生产能力会暂时不可用。

## GTSimpleWirelessNetwork 1.8.8 量子终端

客户端和服务端同时安装本次 Futa 测试版及 **GTSWN 1.8.8** 后：

1. 在基地放置 **公共 ME 接入器**，右键确认它已经连接正常运行的公共网络。
2. 手持 GTSWN 的 **ME 网络量子终端**，普通右键接入器，绑定公共网络。公共核心端口也支持此操作，无需拆开核心寻找控制器。
3. 按 GTSWN 原有操作，用已绑定终端右键普通方块，在点击面放置量子节点，再连接 ME 线缆或设备。支持跨维度，节点及机器所在区块仍须保持加载。
4. 手持终端 **潜行右键公共接入器或核心端口**，仅解除当前终端的公共网络绑定。已经放置的节点、其他玩家的终端和公共网络继续运行。对普通私人控制器的绑定、取消量子化操作保留 GTSWN 原有行为。

首次绑定会调用 GTSWN 自己的权限检查、控制器量子化和绑定存档流程。公共核心的六个合法端口在首次量子化、周期维护和重载时保持连通。

量子节点自动选择一个公共核心端口，并把端口选择保存在节点 NBT 中；以后重连沿用这个端口。它与普通公共接入器共用端口容量，**每端口共 32 频道、六个端口共 192 频道**，增加节点不会扩充总容量。端口满时设备按原生 AE 寻路规则缺少频道；公共网络使用原生频道限制，不触发 GTSWN 的控制器过载爆炸。GTSWN 自带的已用频道统计只统计量子节点分支，查看整个公共网络的实际端口用量请用 `/futame info`。

兼容补丁只对 **1.8.8** 启用，未安装 GTSWN 时不会加载；其他版本需要单独核对其绑定、权限和节点实现。

量子节点的本地线缆接上独立 ME 控制器时，该分支会在维护检查时断开公共桥接，并报告控制器冲突；移除独立控制器后自动重连。不要用量子节点直接合并两套控制器网络。

## B 键入口

按 **B** 打开共享终端，再点 **追踪** 进入统计页：

- **产线管理**：查看每个 IO 的物品、流体领用与回库速率，并组织产线分组。
- **AE 合成**：浏览公共网络中已编码且在线的样板，计算并提交原生 AE 合成任务。

这些附属页面沿用当前共享终端的服务端容器。返回时回到共享终端，页面切换本身不会清空正在使用的本地合成栏。服务器关闭 `allowRemoteAccess` 时，仍需从方块终端进入。

## 产线管理

每条产线具有稳定 UUID 和可修改的名称；每个设备按「类型、维度、坐标、工作面」标识。同一设备只绑定一条产线，再次绑定会转移其归属。相同位置、相同类型和工作面上的替代设备会沿用绑定；设备迁移位置后应更新绑定。

管理员的界面操作顺序为：

1. 新建产线，或在左侧选择已有产线。
2. 点 **所有 IO**，从已记录的设备中选择要加入的 IO。
3. 点 **绑定**；点 **本线 IO** 返回这一条产线的设备列表。
4. 选择设备后，顶部显示该设备的物品、流体双向速率；再点一次同一设备，恢复当前分组汇总。
5. 切换 **原料**，按具体物品或流体查看明细。滚轮查看当前服务端页面里未显示的行，左右箭头翻到下一页。

也可以使用 **产线管理终端**：用一本书、一个指南针和一个红石粉无序合成，或在创造物品栏工具页获取。

1. 手持终端，**Shift + 右键目标 IO**，打开“绑定 IO 到产线”。
2. 确认顶部的设备名称、维度、坐标、工作面与当前产线；直接点击产线即可绑定或转移归属。
3. 没有合适的产线时可现场新建，再点击新产线；“解绑”仅解除当前 IO 的归属。
4. 对空气普通右键打开完整产线管理页，查看整线及每个 IO 的各项原料领用、回库速率。

支持共享 IO 节点、共享终端的 IO 面、原生 AE 物品/流体输入输出总线、存储总线、方块式与面板式 ME 接口，以及实现 AE 网格代理的 GT ME 仓室/总线。AE 线缆上要点到具体总线或接口面板；线缆中心、终端面板和装饰板不作为 IO。GT ME 仓室及方块式 ME 接口按整台设备绑定；共享 IO 与 AE 总线按工作面区分。共享 IO 节点点连接臂会选择该臂，点中心时沿用节点配置界面的选面规则，操作前确认顶部的工作面。

绑定方块式或面板式 **ME 接口 / ME 二合一接口** 后，直接朝向该接口的 **物品存储总线和流体存储总线** 会自动归入同一产线。已有接口绑定也会自动识别，不用重新绑定；后续新贴的总线会在区块加载时被发现。查看整线汇总可同时看到总线领用与接口回库，各总线仍保留独立明细；接口单设备明细只显示接口自身的记录。

自动总线跟随接口改绑和解绑；已被手动指定产线的总线优先保留手动设置。对自动总线不能单独解绑，可操作所属接口，或为总线手动指定另一条产线。取消总线的手动绑定后会恢复跟随接口。绑定页面和设备悬停说明会标明自动归属。

自动关联每秒最多检查 32 个已绑定 AE 请求设备，每个接口只检查相邻六面；面板接口只检查该面。不会加载区块或初始化维度。已确认拆除的总线会移出自动归属；区块暂时卸载时保留已知关联。关系由原有接口绑定重建，不新增持久化绑定字段，服务器重启后随已加载设备重新识别，也不复制或回放搬运记录。

尚未搬运过资源的 IO 也能现场绑定；这只保存归属，不会凭空创建流量或改变机器配置。绑定窗口打开后，移开超过 8 格、切换掉手持终端、拆换目标设备或总线都会使窗口失效。绑定保存后，同坐标、类型和工作面的替代设备仍会沿用原归属。未明确支持的第三方 IO 可继续通过已有记录或 `/futalines bindpos` 管理；绑定能力不会扩展 AE 原有统计的可归因范围，例如 CPU 向接口直接投料不等于该接口从库存领料。

新终端新增一个请求协议，客户端和服务端应同时更新。客户端只在服务端声明支持后发送终端打开请求，连接旧服时给出更新提示；原有库存文件、产线 UUID、绑定和命令格式不变。

创建、重命名、删除、绑定和解绑均要求管理员权限（权限等级 4）；普通玩家可以查询。删除产线只删除分组和绑定，不拆设备，也不改库存。已经绑定的设备即使暂时没有搬运记录，也会保留在列表中。尚未产生活动的设备可以通过坐标命令预先绑定，不需要为此加载目标区块。

### 流速的含义

| 显示项 | 方向 | 单位 |
| --- | --- | --- |
| 物品领用 | 公共仓库 → 设备 | 件/min |
| 物品回库 | 设备 → 公共仓库 | 件/min |
| 流体领用 | 公共仓库 → 设备 | mB/min |
| 流体回库 | 设备 → 公共仓库 | mB/min |

公共网在原生库存处理器实际存取时记录流量，覆盖普通监视器请求和子网直接访问父网库存的优化取料；原料存放在普通 ME 盘或旧共享池都能统计。同一子网同时接物品、流体存储总线时，按资源类型分别确定入口。

统计只累计已完成的实际搬运量；模拟请求不计数。物品和流体分别汇总，具体 NBT 变体在原料明细中保持独立。领用的材料可能仍然留在接口或机器缓存里，因此这些数字表示**设备领用与回库**，不是机器已经完成反应或加工的实际消耗量。原生 AE 请求无法唯一确定产线入口时，会保留可确定的请求设备或未知来源，不猜测生产线。

窗口按钮循环 **1 / 10 / 60 分钟**。实现按服务器启动后的分钟分段累计，包含当前尚未结束的分钟；它不是逐笔时间戳构成的精确滚动窗口。界面同时显示本次统计覆盖的实际观察秒数，速率使用这个时长计算。例如刚启动观察 30 秒，领用 60 件，显示 120 件/min，不会除以尚未观察到的 10 分钟。

跨入新一分钟时，1 分钟视图从新的一段重新累计；观察时间尚不足时显示等待。10/60 分钟视图包括当前部分分钟和前面的分钟段，边界处可覆盖略少于名义窗口的时长。没有记录表示窗口内未观察到搬运，不代表机器已停机、区块已卸载或产线效率为零。

历史分钟统计和趋势**只在内存中保留**，服务端重启后重新积累；产线 UUID、名称、设备绑定、原有入口名称和预警阈值保存到主世界的 `data/futa_gtnh_supply_watch.dat`。历史最多保留一小时，内部资源、设备和配对数有上限；页面提示统计容量达到上限时，数据可能不完整。

### `/futalines` 命令

查询无需管理员权限。页码从 1 开始，省略窗口时默认 10 分钟。

```text
/futalines list [页]
/futalines query [产线UUID|all] [1|10|60] [设备页]
/futalines source <设备ID> [1|10|60] [原料页]
```

以下写操作需要管理员权限：

```text
/futalines create <名称>
/futalines rename <产线UUID> <名称>
/futalines delete <产线UUID>
/futalines bind <产线UUID> <设备ID>
/futalines unbind <设备ID>
/futalines bindpos <产线UUID> <ae_bus|io|ae_machine> <维度> <x> <y> <z> <面>
```

`list` 输出稳定的产线 UUID，`query` 输出可用于绑定和明细查询的完整设备 ID。建议使用 UUID，避免同名产线歧义。`bindpos` 的类型为原生 AE 存储总线 `ae_bus`、共享 IO `io` 或可定位的 AE 请求设备 `ae_machine`。坐标是设备自身的位置；工作面为朝向邻接容器的一面：`0` 下、`1` 上、`2` 北、`3` 南、`4` 西、`5` 东。没有具体工作面的 AE 请求设备可以使用 `-1`。

例如，预先把主世界 `(120, 64, 220)` 朝东的共享 IO 绑定到一条产线：

```text
/futalines bindpos <产线UUID> io 0 120 64 220 5
```

该命令只保存位置绑定，不检查设备是否在线、不放置方块，也不加载它的区块。

## AE 自动合成

1. 在公共网络中配置实际合成 CPU，并在原生 AE 设备中编码、安装样板。
2. 进入 **AE 合成** 页面，左侧搜索和选择已编码且在线的产物。物品和流体都可以出现；流体数量单位为 mB。
3. 输入数量，点 **计算计划**。数量范围为 1 至 1,000,000,000；这个操作只计算，不会启动合成。
4. 右侧检查原料的 **现有 / 待合成 / 缺少** 数量，以及需要的 CPU 存储字节数。缺材料、没有路径或网络不可用时不能提交。
5. 计划就绪后，点 **确认提交**，由原生 AE 合成 CPU 接管执行。修改产物或数量后，需要重新计算，不能用旧预览提交新目标。
6. 在同一页面查看执行、完成、取消或失败状态；需要时点 **取消任务**。退料按原生 AE CPU 规则处理，Futa 不另外复制或返还一份原料。

确认绑定到已显示计划的唯一标识，避免另一个入口更换计划后误提交不同目标。提交时仍可能因为 CPU 忙、容量不足、材料被其他玩家取走或网络变化而被 AE 拒绝；按返回原因处理后重新计算即可。

这个入口不会把 NEI 中所有配方自动变成 AE 样板。手机合成向导、NEI 填栏和手工 3×3 合成继续承担各自的用途。页面只展示已有的在线 AE 样板；极大的目录或异常大的 NBT 条目会受分页与传输上限约束，完整详情可以在原生 AE 终端查看。

每位玩家同时保留一个公共合成会话。关闭页面不会自动取消已经提交的原生任务。玩家离线后是否继续生产取决于 AE 网络、CPU 和机器的加载状态；重启后的已提交任务由 AE 自己保存和恢复，原生 AE 合成状态终端是查看既有任务的入口。

命令入口也可使用同一个服务：

```text
/futame info
/futame plan <数量>
/futame planfluid <mB数量>
/futame confirm
/futame status
/futame cancel
```

`plan` 以手持物品为目标，`planfluid` 以手持已装液容器中的流体为目标。计算和提交遵守公共网络的 AE 合成权限，不要求玩家是产线管理员。

## 配置与验收边界

`config/futa_gtnh.cfg` 的 `publicME` 分类提供公共核心首次建立时的首选坐标：

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| `coreX` | `8` | 首选 X 坐标 |
| `coreY` | `240` | 首选高度 |
| `coreZ` | `8` | 首选 Z 坐标 |

服务端在首选位置附近寻找空位，不覆盖已有建筑；没有合适空位、常加载票据不可用或存档身份不一致时，会报告初始化失败。已经建立核心的世界沿用存档位置，修改这三个值不会搬迁既有核心。

`general.enableSupplyTracking` 控制实际搬运统计，关闭时已保存的产线绑定仍可查询和管理。`allowRemoteAccess` 控制 B 键远程入口。旧库存的专用备份、原始文件和迁移标记应按 [迁移说明](public-me-migration.md) 一起保留。

升级验收应同时检查原生 AE 终端与 B 键终端的库存一致性、物品/流体实际存取、跨维度接入、端口频道耗尽、外部区块卸载、合成 CPU 提交与取消、产线绑定重启持久化。界面截图检查仅证明显示布局可用，不能代替这些实际游戏行为测试。
