# 公共 ME：迁移到原生 AE 存储元件

从 **1.34.0** 开始，共享背包只提供随身访问及兼容 API。实际物品、流体存放在原版 GTNH AE2 / AE2FC 注册的存储元件中，存取和序列化直接使用 AE 的 `CellInventory`；不再把旧共享池包装成一个存储提供者。

公共网按需增加原生 Universe 物品、流体元件。每枚元件仍遵守原生容量和 63 类型规则，满了自动增加下一枚，玩家不需要制作、放置或更换这些元件。资源数量保留 `long` 精度，每种资源最多 `Long.MAX_VALUE`，总类型数没有人为的盘位上限。全服共享、随身访问和跨维度接入沿用现有公共 ME 核心。

## 旧服自动迁移

在玩家和机器能访问库存之前，启动流程执行：

1. 检查原生元件存档及迁移所有权。迁移已完成时只加载当前原生元件，绝不重新导入旧共享文件。
2. 首次迁移沿用旧读取规则验证 `futa_gtnh_shared.dat`；主档损坏时可使用原有 `.bak`，遇到未知版本停止。
3. 对实际读取的源文件建立专用、不可覆盖的原始备份，核对 SHA-256；中断后源文件发生变化则停止续接。
4. 把可用物品、流体逐项存入真正的原生 AE 元件。物品元数据、完整 NBT、流体 NBT 和超过 32 位的数量保持不变；旧限额不会截断库存。
5. 保留已有仓库 UUID、限额、无法解析的旧条目和未决搬运托管。外部箱子、抽屉、储罐和已接入的 ME 盘不复制、不搬空；托管不变成可用库存。
6. 重新打开序列化后的原生元件，逐项核对数量和服务元数据，写入临时文件、同步文件内容、原子提交初始元件存档。
7. 升级旧 AE 认领标记，阻止之前的公共 ME 版本重新打开已归档的共享池；原标记另存备份。最后原子提交新的迁移所有权，才向公共网络发布元件。

新世界直接创建原生存储存档，不创建 `futa_gtnh_shared.dat`。旧文件在迁移后保留原始内容作恢复依据；正常存取、世界保存、显式保存和停服都不再写入旧库存文件。

## 文件

文件均位于主世界存档的 `data/` 目录：

| 文件 | 当前用途 |
| --- | --- |
| `futa_gtnh_public_me_cells.dat` | 正在使用的原生元件 ItemStack NBT，以及限额、托管、隔离条目等服务元数据 |
| `futa_gtnh_native_me_migration.dat` | 原生存储所有权、稳定 UUID、源文件与专用备份校验信息 |
| `futa_gtnh_shared.dat.pre-native-ae-v1` | 本次迁移实际源文件的完整原始备份，永不轮换覆盖 |
| `futa_gtnh_shared.dat` / `.bak` | 已归档的旧共享库存，迁移后不再读写为活动库存 |
| `futa_gtnh_shared.dat.ae-migration` | 升级后的旧版本防误读标记 |
| `futa_gtnh_shared.dat.ae-migration.pre-native-v1` | 如原先存在 v1 认领标记，保留其原始副本 |
| `futa_gtnh_shared.dat.pre-ae-v1` | 更早一次原地认领的历史备份，如存在则继续保留 |

`itemCells` 和 `fluidCells` 保存的是原生存储元件的完整物品 NBT，取出其副本可以直接交给 AE 原生元件处理器读取。服务元数据不再重复保存可用库存的数量表。

## 保存和重载

正常保存由 Minecraft `WorldSavedData` 生命周期驱动，不再运行共享池自己的定时写盘，也不再刷“共享存储已保存”的旧日志。`autosaveIntervalSeconds` 仍供其他辅助档案使用，不控制公共 ME 库存。

`/futashared save` 保存原生元件世界数据。兼容 Hodgepodge 的异步世界保存，显式保存、停服及重载读取前会等待已排队的磁盘写入完成。`reload confirm` 不会先把尚未保存的当前内存重新覆盖到磁盘。

重载失败时保留当前活动库存，并暂停该世界数据的后续保存以保护问题文件；修复后成功重载恢复保存。普通读写仍要求服务端主线程。这里不宣称拥有跨玩家、机器区块、外部容器、ME CPU 与世界存档的崩溃事务。

## 中断与缺失资源

- 原生元件存档已写好、最终所有权尚未提交：验证该原生快照及源备份后续接，不重新追加导入。
- 已完成迁移而原生元件文件丢失、损坏、版本未知或身份不符：停止加载，禁止从旧共享库存自动恢复，以免恢复已经消耗的物品。
- 专用源备份损坏、源文件在中断期间变化、原生媒体不可用或原生元件不能安全接收某项：停止迁移，保留源文件与备份。原生禁止嵌套的非空存储盘也遵守该规则，不能强行改写成普通材料或跳过。
- 缺失模组的旧条目继续以原始 NBT 保留。原生元件中出现无法解析的物品或流体时，整枚元件保留原始 NBT 并暂停发布，避免 AE 加载时删除未知条目；恢复相应模组后可重新挂载。
- 原生媒体数量计数不匹配、条目缺失、负数或不合法元件会拒绝加载，不能用一个空盘代替。

回滚必须停服并恢复同一时刻的完整世界备份，包括原生元件、所有迁移标记、机器与 CPU、玩家和外部容器。不要只换回旧版模组、删除标记或把旧共享快照当作当前库存。旧版本防误读标记仅保护能识别旧认领规则的公共 ME 版本，不能替代完整备份。

## 实际验证

自动回归使用真实 AE/AE2FC 元件和原生库存处理器，覆盖接近 `Long.MAX_VALUE` 的数量、NBT、超过 63 类型扩容、模拟、部分接受、旧句柄失效、元数据、未知条目、坏文件和中断续接。

实机在严格限定的隔离开发存档中，从上一版共享文件和 v1 UUID 迁移，验证超过 32 位的带标签物品、流体、限额与未决托管，随后真实取走 101 件和 203 mB，经世界保存、重载和第二次客户端启动核对已消耗库存没有恢复，旧库存源文件保持原始字节。具体验证命令与范围见 [验证记录](public-me-validation.md)。
